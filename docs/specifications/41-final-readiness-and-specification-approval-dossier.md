# 41 — ملف الجاهزية والاعتماد النهائي للمواصفات

**الإصدار:** 1.0-APPROVAL-CANDIDATE  
**الحالة:** CONSOLIDATED / REVIEW-REQUIRED / NOT-YET-APPROVED  
**المرجع الأساسي:** الفصول 148 و160–163، وسجل القرارات 05، وسجل الفجوات 17، والمصفوفة 40.  
**قاعدة حاكمة:** اعتماد وثيقة المواصفات لا يمنح موافقة بدء البرمجة. يلزم قراران مستقلان وصريحان.

## 1. الغرض ونطاق الاعتماد

هذا الملف هو حزمة مراجعة واعتماد للمواصفات، وليس شهادة بأن كل متطلب أصبح تفصيلياً أو أن الاختبارات نُفذت. يجمع:
- النسخة الموحدة 39.
- قائمة المحاور الأصلية المستعادة ومصفوفة تتبعها 40.
- حالة شروط الجاهزية في الفصل 148.
- معايير نجاح مرحلة المواصفات ومخرجات الفصل 163.
- القرارات المعتمدة والمقترحة والمفتوحة.
- الفجوات المانعة وخطة الإغلاق.

**القرار المقترح حالياً:** اعتماد الحزمة بوصفها مرجعاً موحداً قيد المراجعة فقط، وعدم إعلان الجاهزية للبرمجة، وعدم فتح أعمال تنفيذ برمجية.

## 3. مصفوفة شروط الفصل 148.1

الحالات:
- **مكتمل توثيقياً:** يوجد مرجع موثق، لكن لا يعني أن كل التفاصيل التنفيذية اختُبرت.
- **جزئي:** توجد أجزاء موثقة وتبقى فجوات مؤثرة.
- **مفتوح:** لا توجد مواصفة أو موافقة أو أدلة كافية.
- **مانع:** لا يسمح باجتياز بوابة بدء البرمجة.

## 7. سجل القرارات وحالة اعتمادها

### 7.1 قرارات مثبتة في السجل
ADR-001..020 وADR-023..028 كما وردت في الملف 05، مع ملاحظة أن ADR-021 وADR-022 مصنفتان ARCHITECTURAL DIRECTION وليستا اعتماداً نهائياً لكل تفصيل تنفيذي.

### 7.2 خيارات مبدئية لا يجوز وصفها بأنها معتمدة نهائياً
NestJS/TypeScript، Python، PostgreSQL، S3-compatible storage، pgvector، Redis/Valkey، BullMQ، SSE/WebSocket، OpenTelemetry، GitHub Actions، OIDC/OAuth2 وKeycloak. كل اختيار يحتاج قراراً مستقلاً وفق النطاق والتكلفة والأمن والتوافق.

### 7.3 تعارضات ومناطق لا تزال مفتوحة
- SEC-REV-01: Zero Trust مذكور كإلزامي في 158.7 ومقترح في 158.9؛ يسجل PROPOSED/PENDING_USER وفق الملف 05 حتى توثيق الموافقة.
- C14: المرجع المعتمد هو لوحة التحكم الرئيسية؛ تشغيل واستمرارية الخدمة قدرة مشتركة ضمن L9/L10.
- الفصل 157: لا يوجد متن تفصيلي مستقل في الملفات المصدرية التي جرى فحصها.
- ADR-024..028: القرارات مدرجة APPROVED في الملف 05، لكن رسائل الموافقة الدقيقة لا تحفظ جميعها في الأرشيف الحالي؛ لا تختلق تواريخ أو روابط.
- عتبات الميزانية 50/75/90/100: لا تُعامل كحدود معتمدة حتى تثبيت العملة والسياسة والموافقة.

## 9. خطة الإغلاق قبل إصدار نسخة 1.0 معتمدة

### المسار A — المصدر والقرارات
1. تثبيت مصادر قائمة المحاور الـ64 وربطها بالمصفوفة 40.
2. مراجعة سجل ADR-001..028 والفصل 160 وتوثيق مصدر الموافقات المتاح.
3. إبقاء SEC-REV-01 مقترحاً حتى حسمه.
4. تثبيت C14 ومعالجة مواضع التعارض دون حذف السجل التاريخي.
5. إغلاق مطابقة الفصول 149/162 و148/163، أو توثيق كل فرق مفتوح.

### المسار B — الوظائف والعقود
1. مراجعة كتالوجات C01–C14 بواسطة مالكيها.
2. استكمال عقود SH والخدمات المشتركة والفصل 157.
3. استكمال ملكية البيانات وERD وقاموس الحقول.
4. استكمال APIs/events والصلاحيات والأخطاء والمهل وإعادة المحاولة.
5. استكمال تفاصيل الحقول والأزرار وحالات الواجهة.

### المسار C — الأمن والتشغيل والجودة
1. استكمال عزل المؤسسات والصلاحيات والاختبارات السلبية.
2. استكمال حوكمة الوكلاء وسجل التدقيق.
3. اعتماد سياسات الأسرار والملفات والإضافات.
4. اعتماد RTO/RPO وخطة الاستعادة وإجراء اختبار فعلي.
5. استكمال التكلفة والموارد.
6. إعداد حالات الاختبار وربطها بالأدلة وبيئات التنفيذ.

### المسار D — حزمة التسليم والاعتماد
1. إنشاء PDF وDOCX وExcel للمصفوفات المطلوبة بعد اكتمال المحتوى.
2. تدقيق الروابط والمعرفات والتكرارات والتعارضات.
3. مراجعة تقنية وأمنية مستقلة.
4. إصدار نسخة 1.0-RELEASE-CANDIDATE مع سجل تغييرات وبصمة.
5. عرضها على المستخدم لاعتماد المواصفات فقط.
6. انتظار موافقة منفصلة على بدء البرمجة.
