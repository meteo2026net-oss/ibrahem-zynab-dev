# 186 — الدفعة التنفيذية الرابعة: مصادقة Firebase للويب وإعداد التشغيل

- التاريخ: 2026-11-16
- الفرع: `main`
- النطاق: استبدال حاجز الدخول المغلق بتكامل حقيقي مع Firebase Authentication باستخدام واجهة REST، مع إبقاء المصادقة مغلقة عند غياب الإعداد.

## 1. التنفيذ

- إضافة `provideHttpClient()` إلى إعداد Angular.
- ربط نموذج الدخول بـ Firebase Identity Toolkit `accounts:signInWithPassword`.
- التحقق من البريد وكلمة المرور لدى Firebase؛ لم يعد المتصفح ينشئ جلسة اعتماداً على إدخال شكلي.
- تخزين ID token وrefresh token في ذاكرة الخدمة فقط، وعدم حفظ هوية أو صلاحية في localStorage.
- تحديث ID token عند اقتراب انتهاء صلاحيته باستخدام Secure Token API، مع إبطال الجلسة عند فشل التجديد.
- إسناد الدور الافتراضي `user` فقط؛ لا يوجد منح صلاحية مدير من الواجهة.
- إضافة `public/runtime-config.js` بقيمة فارغة لإعداد Firebase Web API Key دون تضمين قيمة مشروع خاصة في المستودع.
- تحميل إعداد التشغيل قبل Angular من `src/index.html`.

## 2. إعداد Firebase المطلوب قبل تفعيل الدخول

1. في Firebase Console، افتح المشروع المرتبط بتطبيق الويب وأنشئ/اختر Web App.
2. فعّل مزود Email/Password في Authentication.
3. انسخ Web API Key العام من إعدادات تطبيق الويب.
4. ضع المفتاح في `web-angular/public/runtime-config.js` ضمن `firebaseApiKey`.
5. قيّد المفتاح في Google Cloud Console بنطاقات الموقع المسموح بها، وراجع إعدادات Firebase Auth authorized domains.

المفتاح هنا إعداد Firebase Web عام وليس مفتاح خدمة أو مفتاح Admin. لا تضع service-account JSON أو مفاتيح خادم في هذا الملف.

## 3. اختبارات مضافة

- تسجيل الدخول الناجح يمر عبر Firebase ويمنح دور `user` فقط.
- رفض بيانات اعتماد Firebase يبقي الجلسة فارغة.
- localStorage لا يستعيد هوية أو دوراً.
- تجديد ID token يستخدم refresh token الموجود في الذاكرة فقط.
- تسجيل الخروج يمسح الرموز من الذاكرة.

## 4. الحدود

- لا يوجد إنشاء حساب/استعادة كلمة مرور/مصادقة متعددة العوامل بعد.
- لا يتم استرجاع الجلسة بعد تحديث الصفحة؛ الرموز لا تُخزن في المتصفح. يمكن لاحقاً إضافة جلسة خادمية آمنة عند وجود backend يدعم cookies من نوع HttpOnly.
- لا تزال بيانات المشاريع في Angular محلية؛ لم يتم بعد ربط Firestore Web SDK/REST.
- قواعد Firestore المسجلة في Workpaper 178 ما زالت تحتاج إصلاحات P0 قبل تشغيل البيانات الحقيقية.
- لم تُربط أدوار المؤسسة أو العضويات أو موافقات العمليات بالخادم.
- لا يُعد هذا التكامل وحده جاهزية إنتاج كاملة.

## 5. التحقق

- أضيفت اختبارات HTTP mock للمصادقة وتجديد الرموز.
- تشغيل Angular CI لهذه النسخة بانتظار اكتمال workflow؛ لا تُعلن النتيجة حتى مراجعة GitHub Actions.
- لم يتم نشر الموقع.
