## 7. تعريف حالة اختبار قبول قابلة للتنفيذ

لا يُرفع أي سيناريو من SPECIFIED إلى READY قبل احتوائه على:
1. Test ID ثابت ومصدره (source ID أو derived ID معتمد).
2. Requirement ID وFunction ID وOperation/Event ID المرتبطين، مع نوع العلاقة (EXACT أو CANDIDATE).
3. Actor وtenant/project/resource scope والصلاحيات المطلوبة.
4. Preconditions وfixtures وبيانات اختبار غير حساسة وإصدارات ثابتة.
5. خطوات تنفيذ قابلة للتكرار ومدخلات محددة.
6. Expected result مستقل وassertions قابلة للقياس، بما فيها النتائج السلبية.
7. بيئة التشغيل والمنصة وإصدار التطبيق/commit.
8. Runner وrun ID والنتيجة الفعلية وسجلات/تقارير/Artifacts.
9. مراجعة مستقلة وقرار مالك موثق عند الحاجة.

لا تستخدم عنوان السيناريو وحده كـexpected result. ولا تعتبر وجوده في workpaper نجاحاً للاختبار.

## 9. القرارات التي لا يجوز حسمها داخل workpaper

- تعيين Domain SoR أو Qualified OWN أو API Owner أو Decision Owner.
- تحويل مرشح دلالي إلى رابط exact.
- اعتماد أسماء الأحداث المقترحة أو schemas أو producer/consumer.
- اعتماد سياسات الاحتفاظ أو الحذف أو التصدير أو الاستثناءات الأمنية.
- تحديد قيم RTO/RPO أو عتبات الأداء والميزانية غير المعتمدة.
- حسم Zero Trust أو COST/DASH أو تعارضات المصدر دون قرار صاحب الصلاحية.
- إعلان نجاح الاختبارات أو الجاهزية للإصدار دون تشغيل وأدلة فعلية.
