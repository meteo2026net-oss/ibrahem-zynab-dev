## 1. الغرض والمنهج

هذه الوثيقة تستعيد سيناريوهات ومعايير قبول مكتوبة فعلياً في DOCX وتثبت موضع كل مجموعة. لأن بعض الحالات الأصلية بلا معرف Test ID، نستخدم معرفات محلية تبدأ بـ`SRC-AT` لتسهيل الإحالة فقط.

**تحذير:** `SRC-AT-Cxx-nn` معرف locator مشتق لهذه الوثيقة، وليس Test ID أصلياً في DOCX ولا معرفاً معتمداً أو اختباراً منفذاً. لا تساوِ بين هذه المعرفات وبين DRAFT-AT أو Cxx-AT أو EVT-96 أو INT/SEC-80. الحالة لكل السيناريوهات: `SOURCE-TEXT-RECOVERED / NOT EXECUTED`.

## 4. أثر هذه الاستعادة على 80 و102 و99 و100

1. أصبحت لدينا سيناريوهات مصدرية قابلة للإحالة للمراكز C01–C09، وقائمة تحقق اختبارية لـC13، ومعايير اكتمال لـC12/C14، واختبارات أفقية AT/API.
2. لا توجد في هذه الأقسام أسماء Event IDs من سجل 100، لذلك لا يجوز ربط حدث منفرد باختبار على أنه Exact Event Test لمجرد التشابه اللفظي.
3. يمكن إعداد روابط مرشحة بين أحداث المركز وسيناريوهات `SRC-AT`، لكن يجب وسمها `SEMANTIC-CANDIDATE` ومراجعتها مع مالك المجال.
4. بعض عناصر C02/C12/C14 معايير اكتمال وليست Test Cases؛ يجب عدم احتسابها كحالات اختبار منفذة أو مفردة.
5. اختبارات AT/API/DOC في المصدر لها معرفات فعلية داخل الفصول، لكن جميعها مواصفات قبول نصية وليست أدلة تنفيذ.
6. لا تتغير نتيجة الوثيقة 102: لا توجد exact event-specific Test IDs مثبتة في سجل 100 حتى الآن.

## 5. حالة الإغلاق

- المصدر الأصلي والنص المستخرج: مستعادان ومطابقان للبصمة المرجعية.
- سيناريوهات القبول النصية: موثقة بالمواضع أعلاه.
- معرفات SRC-AT: معرفات locator محلية مشتقة، وليست معرفات المصدر.
- الربط المفرد Event→Test: OPEN.
- الربط المفرد Operation→Test: OPEN.
- اعتماد المالكين: OPEN.
- تنفيذ الاختبارات: NOT RUN.
- تغيير كود التطبيق: NOT PERFORMED.

**بوابة التنفيذ:** لا تنشئ هذه الوثيقة APIs أو مخططات أو اختبارات منفذة، ولا تمثل موافقة على بدء البرمجة.
