# 82 — سجل معرفات قرارات الملكية المؤهلة ومطابقة الإحالات

**التاريخ:** 2026-11-15  
**الحالة:** DERIVED TRACEABILITY CONTROL / OWNER REVIEW REQUIRED / NOT APPROVED / NO IMPLEMENTATION  
**المصادر:** الوثائق 36 و72 و76 و77–81.

## 1. الغرض

تمنع هذه الوثيقة التباس معرفات قرارات الملكية المتكررة. لا تعيد تسمية المعرفات التاريخية في مصادرها، ولا تعتمد أي قرار، بل تعرف صيغة إحالة مؤهلة يجب استخدامها في الوثائق الجديدة والتحديثات اللاحقة.

## 3. إحالات الوثيقة 77 بعد التأهيل

الإحالات في جدول التداخلات بالوثيقة 77 تقصد سجل الوثيقة 72/76، لذا يجب قراءتها كما يلي:

| موضع الوثيقة 77 | الإحالة المختصرة السابقة | الإحالة المؤهلة |
|---|---|---|
| FLD-09 asset registry/storage | OWN-01 | OWN72-01 |
| FLD-12 connector/secrets | OWN-02 | OWN72-02 |
| FLD-17/18 knowledge/index/search | OWN-04 | OWN72-04 |

أما العناصر التي ما زالت OPEN في الوثيقة 77 فلا تكتسب قرار ملكية لمجرد وجود رقم مماثل في الوثيقة 36. ولا يغلق هذا السجل FLD-01..26.

## 4. قواعد الإحالة للعقود والاختبارات

1. أي إحالة إلى قرارات الوثيقة 36 تستخدم OWN36-nn.
2. أي إحالة إلى حزمة قرارات الوثيقتين 72/76 تستخدم OWN72-nn.
3. لا تستخدم OWN-nn منفرداً في الوثائق الجديدة أو الاختبارات.
4. كل API/Event/Approval يجب أن يذكر Domain SoR وDomain Owner وAPI Owner وقرار الملكية المؤهل، أو يصرح بأن القرار OPEN.
5. كل اختبار يقيس حد ملكية يجب أن يذكر معرف القرار المؤهل، ومعرف العقد، ومعرف المتطلب، وحالة التنفيذ.
6. لا يجوز تحويل توصية مشتقة إلى حالة APPROVED أو EXECUTED دون قرار موثق أو دليل تشغيل.

## 7. الاعتماد والحدود

- يجب أن يراجع ملاك C01–C14 وSH-01–SH-16 مطابقة النطاقات وأصحاب القرار.
- يجب تحديث الوثيقة 36 بعد اعتماد فعلي فقط، مع إبقاء معانيها التاريخية وسجل التغييرات.
- لا تُنشئ هذه الوثيقة مخطط بيانات أو API أو صلاحيات أو جداول أو كوداً.
- لم تُنفذ الاختبارات ولم تُسجل موافقات.
- تبقى موافقة بدء البرمجة مستقلة وصريحة بعد اكتمال واعتماد المواصفات.
