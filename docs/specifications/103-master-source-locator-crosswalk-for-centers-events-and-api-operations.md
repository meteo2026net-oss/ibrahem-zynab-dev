## 4. إعادة تقييم سجل الأحداث 100

يحتوي سجل 100 على **106 Event IDs**. بعد استعادة النص المصدر، أصبحت لدينا locators دقيقة على مستوى الفصل/المركز كما في القسم 2. لكن ذلك لا يكفي وحده لرفع أي صف من `CENTER-LEVEL` إلى `EVENT-LEVEL`.

- تبقى أسماء الأحداث الـ106 كما هي في سجل 100، بوصفها أسماء مشتقة من عقود المراكز 59–70 وسجل الأحداث 96.
- يجب عدم كتابة رقم سطر فصل المركز في كل صف وكأنه إثبات أن اسم الحدث نفسه وارد في تلك الفقرة.
- لكل حدث يلزم فحص فقرة مصدرية محددة تتناول انتقال المجال نفسه، ثم توثيق عنوان الفقرة/النص المرجعي/السطر.
- إذا لم يوجد نص مصدري صريح للحدث، يبقى `DERIVED-NOT-VERBATIM` مع الإشارة إلى العقد الوسيط، ولا يُرفع إلى `SOURCE-RECOVERED` لمجرد أن المركز موثق.
- تبقى Domain producer وDomain SoR وQualified OWN وExact Test ID حقولاً مستقلة، ولا تُملأ من اسم المركز أو من عائلة اختبار عامة.

**النتيجة:** لم تُغلق هذه المراجعة فجوة الاختبارات المفردة في 102، ولم تغيّر عدد الأحداث أو حالات المصدر في 100. إنها تضيف مصدر locator موثوقاً على مستوى المركز وتمنع الإحالة الزائفة إلى فقرة غير محددة.

## 5. إعادة تقييم سجل عمليات API 97/99

يحتوي سجل 97/99 على **201 Operation ID**. المراجع 59–70 عقود وسيطة مشتقة، بينما يتيح DOCX الآن locators للفصول الوظيفية. ومع ذلك:

1. لا يثبت وجود وظيفة في الفصل أن اسم `operation` في 97 هو اسم API أصلي معتمد.
2. لا يثبت عنوان الفصل شكل request/response أو schema أو error contract.
3. لا يثبت locator المركز أن كل محور AX المرشح في 99 ينطبق على العملية.
4. يجب أن يحتفظ كل صف بمصدر العقد الوسيط، ويضيف source locator دقيقاً فقط بعد تحديد فقرة وظيفية بعينها.
