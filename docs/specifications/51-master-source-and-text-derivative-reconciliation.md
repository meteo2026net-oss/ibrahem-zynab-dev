## 2. ما الذي تمت مراجعته فعلياً

تمت قراءة النسخة النصية `00_MASTER_SPECIFICATION.md` كاملة من المستودع. تتضمن:
- الرؤية والنطاق والمبادئ المعمارية.
- 14 مركزاً وظيفياً بعناوين وتفاصيل أولية للشاشات والأزرار.
- معرّفات وظيفية FR، ومتطلبات غير وظيفية NFR.
- 12 مرحلة تنفيذية و7 بوابات G0–G6.
- معايير قبول ومخاطر.
- أمثلة تفصيلية وسيناريو متجر «متجري».

رأس الوثيقة يقول إنها مستخرجة من إصدار 0.3 DRAFT مع قرارات التوثيق، وحالتها «جاهز للمراجعة والاعتماد»، بينما يصف الجزء التاسع الوضع بأنه 0.3 DRAFT ويطلب اعتماد الوثيقة وإكمال سد الفجوات. لذلك فهي مرشح موحد للمراجعة وليست دليلاً على اعتماد نهائي.

## 3. تعارضات جوهرية بين النسخة النصية والقرارات/المواصفات اللاحقة

### 3.1 أسماء المراكز وحدودها

النسخة النصية تصف توزيعاً مختلفاً للمراكز، مثل:
- C01 مركز المشاريع
- C02 مركز التحليل
- C03 مركز التصميم
- C04 مركز الوظائف
- C05 مركز البيانات
- C06 مركز الوكلاء
- C07 مركز البناء
- C08 مركز الاختبار
- C09 مركز الإطلاق
- C10 مركز المراقبة
- C11 مركز الأمان
- C12 مركز الإعدادات
- C13 مركز التعاون
- C14 مركز التقارير والإحصاءات

أما خريطة المراكز اللاحقة المعتمدة في `02-centers-and-screens.md` وسجل ADR-023 فتحدد:
- C01 إنشاء المشروع وتحليل المتطلبات
- C02 مساحة التصميم
- C03 الصفحات والتنقل
- C04 البيانات وقواعد البيانات
- C05 البرمجة
- C06 فريق الذكاء الاصطناعي
- C07 الاختبارات وضمان الجودة
- C08 الملفات والوسائط
- C09 التكاملات والخدمات الخارجية
- C10 الأمن والحوكمة
- C11 البناء والنشر
- C12 المعرفة والتوثيق
- C13 الإعدادات
- C14 لوحة التحكم الرئيسية

**الحكم:** لا تُستخدم أرقام المراكز في النسخة النصية كمرجع حالي منفرد. يلزم توثيق خريطة تحويل بين التسميتين، والمحافظة على تفاصيل الوظائف الأصلية التي لا تزال مطلوبة، وإزالة أي التباس في معرفات Cxx-Sxx قبل اعتماد الشاشات. المرجع التشغيلي الحالي هو قائمة 02 وسجل ADR-023، مع إبقاء أي تعارض تاريخي موثقاً.

### 3.2 الطبقات العشر

النسخة النصية تسمي الطبقات «10 طبقات مقترحة» وتعرض: UI، Presentation، Business Logic، Agents Orchestration، IR، Code Generation، Data & Models، Integration، Security & Auth، Infrastructure & Observability.

الوثيقة `06-ten-layer-architecture.md` تصف التقسيم الرسمي المعتمد:
L1 واجهة المستخدم؛ L2 تجربة التصميم؛ L3 إدارة المشاريع؛ L4 محرك الذكاء الاصطناعي؛ L5 محرك التنفيذ؛ L6 البيانات والتكاملات؛ L7 الجودة والتحقق؛ L8 الأمن والحوكمة؛ L9 التشغيل والاستمرارية؛ L10 البنية التحتية.

**الحكم:** قائمة الطبقات في Markdown هي تصور سابق/مقترح وليست مرجع التقسيم الرسمي الحالي. لا يجوز إسقاط L7 وL9 أو دمج وظائفهما في قائمة قديمة دون توثيق.

### 3.3 متطلبات غير وظيفية وأرقام تحتاج قراراً

تورد النسخة النصية أرقاماً ومقاييس منها:
- استجابة عمليات شائعة ≤2 ثانية.
- تحميل الصفحة الرئيسية ≤3 ثوانٍ.
- 50 مستخدماً متزامناً في المرحلة الأولى.
- معاينة حية ≤1 ثانية.
- توفر ≥99.5%.
- نسخ احتياطي يومي.
- WCAG 2.1 مستوى A.

في المقابل، الوثائق اللاحقة تتعامل مع قياسات الأداء والسعة وأهداف الخدمة وRTO/RPO بوصفها قرارات تحتاج اعتماداً، وتذكر WCAG 2.2 AA كهدف افتراضي عند الملاءمة، وليس نتيجة اجتياز.

**الحكم:** الأرقام الواردة في Markdown تُسجل كقيم مصدرية مرشحة للمراجعة (SOURCE-REFERENCE-FOUND / OWNER-REVIEW)، ولا تُرفع إلى NFR معتمدة قبل حسم النطاق وطريقة القياس والبيئة والمالك. لا تُستبدل قيمة معيار الإتاحة أو تُعتبر اجتيازاً دون قرار واختبار.

### 3.4 نطاق المنصات

النسخة النصية تذكر Android وiOS والويب وسطح المكتب، وتقترح Electron أو ما يعادله لسطح المكتب مع وصفها مرحلة لاحقة. المرجع الموحد اللاحق يحدد Windows وmacOS وLinux صراحةً ضمن نطاق المنصات.

**الحكم:** احتفظ بالنطاق اللاحق الصريح، ولا تعتبر اقتراح Electron قراراً نهائياً.

### 3.5 الحوكمة والمراحل

النسخة النصية تنص صراحة على منع البرمجة قبل استعادة المواصفات واعتمادها وعبور G1، وتعرض 12 مرحلة و7 بوابات. هذا متسق مع الفصل بين اعتماد المواصفات وموافقة بدء البرمجة، لكنه لا يثبت عبور G1 أو اكتمال المواصفات.

### 3.6 موضوعات غير موجودة في الملخص النصي

لم يظهر في `00_MASTER_SPECIFICATION.md` نص صريح للفصل 157 أو SH-17..SH-20 أو SEC-REV-01 أو Multi-Tenant أو الفصل 163. لا يثبت ذلك غيابها من DOCX الرئيسي الكبير؛ الملخص النصي لا يُعامل كبديل كامل له. هذه الموضوعات تبقى محكومة بمصادرها المتخصصة وتقارير التدقيق السابقة حتى مراجعة DOCX الكامل.

## 4. أثر المطابقة على التقارير السابقة

1. يصحح التقرير 50: ملف DOCX الرئيسي موجود؛ المانع ليس غيابه من GitHub بل عدم استخراج محتواه الثنائي عبر قناة القراءة الحالية.
2. تمت قراءة Markdown الملخص بالكامل، لكنه لا يحل محل المصدر الكامل.
3. يجب إضافة هذا التقرير إلى سجل المصادر والمرجع الموحد.
4. لا تتغير نتيجة GAP-044؛ مراجعة المراجع للمحاور الـ64 لا تعني إغلاق التتبع أو اعتماد المالك.
5. لا يبدأ التنفيذ البرمجي قبل إغلاق بوابة G1 وموافقة المستخدم المستقلة.

## 5. المطلوب لاستكمال المطابقة

- استخراج محتوى DOCX ذي 6.8MB من المستودع عبر مسار يدعم الملفات الثنائية أو إرفاق نسخة نصية مستخرجة منه في المستودع.
- التحقق من الصفحات والجداول والملاحق والصور/المخططات وعدم الاكتفاء بالنص المستخرج إن كان المستند يحتوي عناصر مرئية.
- مقارنة فصول DOCX الرئيسي مع الملفات 01–50، مع تسجيل الفروقات بندياً ومصدر كل قرار.
- إعداد جدول تحويل شامل لمعرفات المراكز والشاشات القديمة إلى القائمة الحالية، دون افتراض تطابق أرقام الشاشات.
- مراجعة كل قيمة NFR رقمية مع مالك المنتج والمعمارية والتشغيل والجودة.
- إبقاء القرارات غير المحسومة مفتوحة حتى يظهر مصدر موافقة صريح.

## 6. خلاصة الدليل

**المثبت:** وجود ملف DOCX رئيسي كامل في GitHub بحجم 6,794,517 bytes، ووجود نسخة Markdown منظمة تمت قراءتها بالكامل، ووجود اختلافات واضحة بين هذه النسخة النصية وبين تقسيم المراكز والطبقات اللاحق.

**غير المثبت:** محتوى DOCX الرئيسي الكامل، مطابقة جميع ملاحقه، اعتماد أرقام NFR، أو اكتمال/اعتماد أي اختبار تنفيذي.

**القرار:** SOURCE-FOUND؛ TEXT-DERIVATIVE-REVIEWED؛ FULL-DOCX-CONTENT-REVIEW-PENDING. لا تطلب من المستخدم إعادة رفع الملف لمجرد أن أداة قراءة GitHub الحالية لا تعرض محتواه الثنائي.
