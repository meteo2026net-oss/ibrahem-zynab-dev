## 1. الفصل 132 — المعمارية الداخلية والخدمات المشتركة

### 1.1 أهداف المعمارية (132.1)

- تشغيل المراكز الأربعة عشر ضمن منصة واحدة.
- منع تداخل المسؤوليات وتوحيد الخدمات المشتركة.
- دعم إضافة مراكز وتقنيات ومنصات ومزودي AI مستقبلاً.
- فصل واجهة المستخدم عن محركات التنفيذ.
- دعم العمل المتزامن والمهام الطويلة.
- حماية البيانات والملفات ودعم الاستعادة والمراقبة.
- تقليل الاعتماد على مزود تقني واحد.
- تسهيل الاختبار والتطوير والصيانة.

### 1.2 توزيع المراكز (132.2)

الفصل 132.2 يثبت القائمة التي تجعل المركز الرابع عشر لوحة التحكم الرئيسية، وهو متسق مع القرار المعتمد الحالي:
1. إنشاء المشروع وتحليل المتطلبات.
2. مساحة التصميم.
3. الصفحات والتنقل.
4. البيانات وقواعد البيانات.
5. البرمجة.
6. فريق الذكاء الاصطناعي.
7. الاختبارات والجودة.
8. الملفات والوسائط.
9. التكاملات والخدمات الخارجية.
10. الأمن والحوكمة.
11. البناء والنشر.
12. المعرفة والتوثيق.
13. الإعدادات.
14. لوحة التحكم الرئيسية.

قاعدة الملكية في المصدر: كل مركز مسؤول عن منطق مجاله وقراراته الوظيفية، ويستهلك الخدمات المشتركة دون تكرار قواعد العمل.

### 1.4 واجهة Angular (132.4)

الوحدات المذكورة: Application Shell، Main Dashboard، Project Workspace، Center Navigation، Design Workspace، Code Workspace، AI Workspace، Document Workspace، Settings Workspace، Notification Center، Global Search، Approval Center.

الخصائص:
- العربية RTL والإنجليزية LTR.
- الشاشات الكبيرة والمتوسطة والصغيرة.
- تخصيص مساحة العمل وتعدد المشاريع.
- اختصارات لوحة المفاتيح والوضع الفاتح والداكن.
- تحديث الحالة دون إعادة تحميل كامل.
- عرض المهام الطويلة والأخطاء بصورة مفهومة.

الضوابط: الواجهة لا تخزن الأسرار، ولا تنفذ قرارات الصلاحيات، ولا تعتمد على إخفاء الأزرار كحماية، ولا تعتبر نجاح الطلب دليلاً على نجاح العملية الخلفية.

### 1.5 طبقة API (132.5)

المكونات المقترحة: API Gateway، REST API، WebSocket Gateway، Authentication Middleware، Authorization Middleware، Request Validation، Rate Limiting، API Versioning، Error Handling، Request Correlation.

المعايير: التحقق من الهوية والصلاحيات، التحقق من المدخلات، إصدارات العقود، عدم كشف التفاصيل الداخلية، معرف موحد للطلب، بنية أخطاء موحدة، وإعادة محاولة لا تكرر الآثار غير الآمنة.

يوضح المصدر endpoint تجريبياً لتوليد الكود؛ المثال شكل تعليمي وليس API منشوراً.

### 1.6 الخدمات المشتركة (132.6)

قائمة الخدمات SH-01..SH-16 موثقة في الملف 23. الفقرات 132.6.1–132.6.8 تفصل الهوية والصلاحيات والموافقات والتدقيق والإشعارات والملفات والبحث والمهام. لا يقدم المقطع المستعاد تفاصيل مرقمة مماثلة لـSH-09..SH-16.

### 1.7 خدمات المراكز (132.7)

كل مركز يحدد مسؤولياته وبياناته المملوكة وواجهاته المقدمة والمستهلكة وقواعد العمل والصلاحيات وحالات العمليات والأحداث والاختبارات ومؤشرات الصحة. لا يجوز لمركز تعديل جداول مركز آخر مباشرة متجاوزاً واجهاته وقواعده.

### 1.8 محركات التنفيذ المستقلة (132.8)

- Code Generation Engine.
- Code Analysis Engine.

المبدأ: يمكن استبدال المحرك أو إضافة محرك آخر مع المحافظة على عقد adapter، دون إعادة كتابة واجهة Angular بالكامل.

### 1.9 تنسيق AI (132.9)

المكونات: AI Orchestrator، Agent Registry، Model Registry، Provider Adapters، Skill Registry، Tool Registry، Memory Service، Policy Engine، AI Task Scheduler، Evaluation Engine، AI Cost Manager، AI Audit Logger.

دور Orchestrator: فهم المهمة، تقسيمها، اختيار الوكلاء، توزيع العمل، ترتيب الاعتماديات، متابعة النتائج، كشف التعارضات، طلب الموافقات، تجميع النتائج والتقرير. لا يمتلك سلطة مطلقة.

قواعد: لا يرفع الوكيل صلاحياته، ولا يتجاوز رفض الموافقة، ولا يقرأ ذاكرة مشروع آخر، ولا يغير سياسات النظام، ولا يعتمد مخرجاته الحساسة بنفسه؛ مع تسجيل الأدوات وحدود الوقت والتكلفة والمحاولات.

### 1.10 البيانات والتخزين (132.10)

أنواع التخزين المذكورة: Relational Database، Object Storage، Search Index، Vector Index، Cache، Event Store أو سجل أحداث، Backup Storage.

القواعد: مالك لكل كيان، معرفات موحدة، نطاق مؤسسة/مشروع، فصل البيانات التشغيلية عن التدقيق، retention، الأسرار خارج جداول الإعدادات العادية، schema versions، معاملات عند الحاجة، وعدم جعل cache مصدراً للحقيقة.

### 1.11 الأحداث والرسائل (132.11)

الأحداث أمثلة: project.created، requirements.approved، design.approved، navigation.updated، database.schema.approved، code.generation.completed، code.delivery.approved، qa.tests.completed، security.review.completed، integration.activated، build.completed، deployment.approved، knowledge.document.approved.

بنية الحدث التوضيحية تشمل eventId وeventType وeventVersion وprojectId وsourceCenter وoccurredAt وcorrelationId وpayload.

القواعد: لا أسرار في الأحداث، تحقق من المصدر، معالجة idempotent، عدم افتراض ترتيب مثالي، حفظ الفشل وإعادة المعالجة وربط الحدث بالعملية المنتجة.

### 1.12 المهام الطويلة (132.12)

حالات المصدر: Created، Queued، Scheduled، Running، Waiting Approval، Paused، Retrying، Completed، Failed، Cancelled، Expired.

الخصائص: الأولوية والمالك والوكيل والمهلة والميزانية والاعتماديات والتقدم والإيقاف والاستئناف والمحاولات والمخرجات وأسباب الفشل.

قاعدة حاكمة: retry لا يعني إعادة تنفيذ الآثار الجانبية المكتملة تلقائياً.

### 1.13 الإضافات والمحولات (132.13)

أنواع الإضافات: تقنيات البرمجة، قواعد البيانات، AI، التخزين، المصادقة، البناء، النشر، أدوات التصميم، الاختبار، المراقبة.

كل manifest يحتاج معرفاً وإصداراً ومطوراً ونوعاً وقدرات وواجهات وصلاحيات واعتماديات وتوافقاً وترخيصاً ومتطلبات تشغيل وتحديث وإيقاف وفحصاً أمنياً.

وجود الإضافة في الكتالوج أو توقيعها لا يعني السماح بتشغيلها تلقائياً.

### 1.14 الاتصال بين الخدمات (132.14)

- الاتصال المتزامن للاستعلامات والعمليات القصيرة.
- الاتصال غير المتزامن للمهام الطويلة والأحداث والتدفقات.

كل عقد يوثق اسم الخدمة والعملية والطلب والاستجابة والأخطاء وإعادة المحاولة والمهلة والصلاحيات وحدود الاستخدام والإصدار.

### 1.15 المراقبة والاستمرارية (132.15)

المؤشرات: صحة الخدمات، زمن الاستجابة، معدل الأخطاء، الذاكرة والمعالج، ضغط قواعد البيانات، طول الطوابير، فشل المهام، توفر مزودي AI، التكاملات، التخزين، التكلفة.

لا يحدد الفصل أرقاماً نهائية للتوافر أو الاستعادة؛ يجب تحديدها بعد دراسة الموارد والتكاليف ونطاق التشغيل.

### 1.16 فصل البيئات (132.16)

Development، Testing، Staging، Production، Sandbox. لكل بيئة إعدادات وصلاحيات وأسرار وبيانات وحدود موارد وسياسات اتصال وسجلات مستقلة. لا تستخدم بيانات إنتاج حساسة في الاختبار دون سياسة صريحة وضوابط.

### 1.17 الأمن المعماري (132.17)

المجالات: المصادقة، تفويض خادمي، عزل المؤسسات والمشاريع، تشفير الاتصالات، الأسرار، الجلسات، حدود الطلبات، التدقيق، فحص الملفات، عزل تنفيذ الكود، حماية APIs، مراقبة الإضافات، سياسات AI، دورة حياة البيانات والاستجابة للحوادث.

### 1.18 اختبارات المعمارية (132.19)

المعرفات المستعادة AT-01..AT-15:

- انقطاع الواجهة دون فقد حالة المهام.
- رفض الوصول لمشروع آخر.
- عدم تكرار آثار الحدث المكرر.
- استعادة المهمة عند توقف عامل.
- بديل معتمد أو توقف واضح عند تعطل مزود AI.
- رفض الاتصال عند انتهاء السر.
- رفض تجاوز الوكيل لصلاحيته.
- استمرار الخدمات الأساسية عند فشل البحث.
- عدم إعلان نجاح رفع ملف فاشل.
- كشف تعارض إصدار API.
- استعادة نسخة احتياطية قابلة للتحقق.
- إضافة محرك دون إعادة بناء جميع المراكز.
- تحديث Angular دون تغيير منطق المحرك الداخلي.
- متابعة المهمة الطويلة وإيقافها وفق السياسة.

## 2. الفصل 133 — معمارية الواجهة وتجربة المستخدم الموحدة

### 2.1 أهداف تجربة المستخدم

الوصول السريع للمراكز، تقليل ازدحام الواجهة، دعم المبتدئ والمحترف، تجربة موحدة، حالة مشروع مفهومة، مساعد AI اختياري، تحكم واضح بالمهام، لوحات متعددة، العربية والإنجليزية، وتخصيص مساحة العمل.

### 2.2 الهيكل العام

Top Bar، Main Sidebar، Project Switcher، Center Navigation، Workspace Area، AI Assistant Panel، Activity Panel، Notification Center، Approval Center، Status Bar.

### 2.3 الشريط العلوي

الشعار، المشروع الحالي، البحث العام، إنشاء عنصر، المساعد الذكي، المهام الجارية، الإشعارات، إعدادات الحساب، اللغة والمظهر. لا يفقد سياق المشروع عند الانتقال بين المراكز.

### 2.4 القائمة الجانبية

تعرض المراكز الأربعة عشر ضمن مجموعات قابلة للطي والتوسيع، مع حفظ تفضيل المستخدم.

### 2.5 مساحة المشروع

تعرض الاسم والوصف والحالة والمنصات والتقنية المعتمدة والأعضاء والمراكز النشطة والأنشطة والمهام والوثائق والتنبيهات ومؤشرات اكتمال قابلة للتفسير. يمنع عرض نسبة إنجاز وهمية بلا معايير وأوزان واضحة.

### 2.6 مساحات العمل المتعددة

Single Workspace، Split Workspace، Multi-Panel Workspace، مثل التصميم بجانب المعاينة، الكود بجانب الأخطاء، الوثيقة بجانب المتطلبات. العدد والحدود يراعيان قدرات الجهاز والأداء.

### 2.7 المساعد الذكي العام

متاح في المراكز مع مراعاة السياق؛ يشرح ويحلل ويلخص ويقترح المهام والخطط ويستدعي الوكلاء المصرح لهم. يعرض الوكيل والأدوات والملفات والتغييرات والتكلفة عند توفرها، ولا ينفذ تغييرات مهمة بصمت.

### 2.8 الأنشطة والمهام والموافقات

لوحة الأنشطة تعرض اسم العملية ومشروعها ومركزها ومسؤولها وحالتها ووقت البدء والتقدم والمدة والنتيجة والأخطاء والإجراءات المتاحة. مركز الموافقات يعرض السبب والجهة الطالبة والأثر والخطورة والملفات والتكلفة والبدائل والقرار المطلوب.

### 2.9 البحث العام

بحث المشاريع والوثائق والملفات والمكونات والمتطلبات والكود والمهام والقرارات والتكاملات، مع احترام الصلاحيات وإظهار المصدر.

### 2.10 إعدادات الواجهة والاختبارات

اللغة والاتجاه والمظهر وحجم الخط وكثافة العناصر والتخطيط والاختصارات والإشعارات والمساعد والعرض.

اختبارات UX-01..UX-10 تشمل حفظ سياق المشروع، صحة RTL/LTR، عدم إتاحة مركز غير مصرح عبر API، استمرار حالة المهام، عمل اللوحات دون تضارب، احترام صلاحيات البحث، إظهار تفاصيل الموافقة، عرض انقطاع الاتصال، حفظ المظهر، ومنع تسرب السياق بين المشاريع.

## 3. قرارات تحتاج مطابقة

1. الفصل 132 يذكر 10 طبقات منطقية تختلف عن قائمة الطبقات الرسمية L1–L10؛ مطلوب crosswalk وليس استبدال.
2. الفصل 132 يصف قائمة الخدمات SH-01..SH-16؛ الفصل 157 مذكور لاحقاً في مصدر الفصل 155 على أنه مطلوب لتوحيد المكونات والخدمات، ولم يستعد نصه التفصيلي بعد.
3. أسماء الاختبارات AT-01..AT-15 وUX-01..UX-10 يجب مطابقتها مع أي معرفات حديثة متشابهة لتجنب تكرار IDs بين نطاقات مختلفة.
4. بعض قرارات الفصل 132 و133 معنونة «مقترحة» ولا تعتبر اعتماداً تلقائياً.
5. C14 في الفصل 132.2 هو لوحة التحكم الرئيسية؛ لا يجوز استيراد تسمية «التشغيل والاستمرارية» الواردة في بعض النصوص التاريخية كاسم مركز.

**الخلاصة:** تمت استعادة البنية الداخلية وتجربة المستخدم للفصلين 132 و133. هذه إضافة مصدرية مهمة، لكنها تحتاج توحيداً مع الطبقات الرسمية وسجل القرارات والمواصفات الحالية قبل اعتماد الإصدار النهائي.
