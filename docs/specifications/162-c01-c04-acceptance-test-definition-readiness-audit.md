# 162 — تدقيق جاهزية تعريف اختبارات القبول للمراكز C01–C04

**التاريخ:** 2026-11-16  
**الحالة:** SOURCE-VERIFIED TEST-ID AUDIT / INCOMPLETE TEST DEFINITIONS / NOT EXECUTED / OWNER REVIEW REQUIRED  
**المصادر:** Export 07 B-01..B-04؛ السجل 143؛ جرد المعرفات 141؛ مطابقة الأحداث 156؛ تسوية العمليات والاختبارات 155؛ سجل العمليات 97.

## 1. الغرض

فحص ما إذا كانت معرفات اختبارات القبول المصدرية للمراكز C01–C04 قد تحولت فعلاً إلى حالات اختبار قابلة للتنفيذ، مع الفصل بين وجود معرف الاختبار، ووصف السيناريو، والنتيجة المتوقعة، والربط بعملية أو حدث، والتنفيذ بالدليل.

## 3. حدود تعريف الحالة الحالية

وجود Test ID ووصف سيناريو لا يوفر تلقائياً:
- شروطاً مسبقة أو حالة بيانات معروفة.
- خطوات تنفيذ دقيقة قابلة للتكرار.
- نتيجة متوقعة قابلة للقياس.
- assertions أو معايير رفض/نجاح.
- بيئة ومنصة وإصداراً محدداً.
- fixture أو بيانات اختبار معزولة.
- روابط دقيقة إلى Function ID وOperation ID وEvent ID وApproval ID.
- run ID ونتيجة فعلية ودليلاً قابلاً للمراجعة.

### 3.1 C01 — حالات لها نتائج متوقعة مصدرية

المعرفات C01-AT-01..15 لها نتائج متوقعة منفصلة في Export 07، مثل إنشاء مشروع بصلاحية صحيحة، ورفض الإنشاء دون صلاحية، وحفظ المرجع، وإظهار استخراج المستند كاقتراح غير معتمد، وتسجيل التعارض، ومنع الاعتماد غير المصرح، وحفظ خط الأساس، وعزل المؤسسات، والأرشفة، ونقل المدخلات المعتمدة فقط.

هذه النتائج مصدرية لكنها لا تزال ليست تنفيذات ناجحة. كما تحتاج إلى تحويلها إلى خطوات وبيانات واختبارات قابلة للتكرار وربطها بالعمليات والأحداث ذات الصلة.

### 3.2 C02 — 15 سيناريو دون نتيجة متوقعة مستقلة

تشمل السيناريوهات إنشاء مساحة تصميم، وتحرير الصفحات والعناصر والطبقات والمكونات والخصائص، والتحرير من المعاينة، والتراجع، وRTL، وتعدد المنصات، واختلافاتها، ومقترحات AI، والإصدارات، ورفض الاعتماد دون صلاحية.

يلزم تعريف oracle لكل سيناريو؛ خصوصاً سلامة التراجع، وعدم الكتابة فوق نسخة معتمدة، وثبات سلوك RTL، ومقارنة المنصات، وحدود اقتراح AI مقابل التطبيق، وتفويض قرار الاعتماد.

### 3.3 C03 — 18 سيناريو دون نتيجة متوقعة مستقلة

تشمل إنشاء الصفحات وخريطة التنقل والمسارات، كشف الروابط والصفحات غير الموجودة أو المعزولة، الانتقالات المشروطة، القوائم وأشرطة التنقل، حماية الصفحات، الروابط العميقة، رحلة المستخدم، اقتراح AI، الاعتماد، حفظ الإصدارات، واختلاف المنصات.

يلزم تعريف oracle يميز بين صحة graph وصحة route وسلوك runtime، وبين إعداد حماية الصفحة وتفويض الوصول الخلفي المركزي. لا يُعد إخفاء الصفحة أو عنصر الواجهة اختباراً أمنياً كافياً.

### 3.4 C04 — 20 سيناريو دون نتيجة متوقعة مستقلة

تشمل مصادر البيانات والمخططات والجداول والحقول والأنواع والعلاقات والقيود وRLS والاستعلامات وربط الواجهات والبيانات التجريبية والمزامنة والملفات وسلامة البيانات والترحيل والنسخ والاستعادة والمقارنة مع الكود والاعتماد.

يلزم تعريف oracle مستقل لكل من عزل RLS بين المؤسسات، وسلامة العلاقات والقيود، وتسوية تعارض المزامنة، وحدود التخزين C04/C08، وسلامة الترحيل والتراجع، والتحقق من الاستعادة. لا يمكن إعلان نجاح backup بمجرد إنشاء ملف نسخة، ولا نجاح restore دون التحقق من المحتوى والتناسق.

## 4. تقاطع الاختبارات مع الأحداث

الوثيقة 156 تحتوي 26 مرشحاً دلالياً لأحداث C01–C04 وربطها بـSRC-AT locators:
- C01: 6 أحداث/6 مرشحات.
- C02: 5/5.
- C03: 5/5.
- C04: 10/10.

هذه المصفوفة لا تنشئ روابط exact Event→Test؛ عدد الروابط المعتمدة ما زال **0/26** لهذه المراكز. SRC-AT معرف locator محلي في الوثيقة 104، وليس معرف اختبار أصلياً أو بديلاً عن Cxx-AT-nn. كما أن المرشح الدلالي لا يثبت أن السيناريو يغطي event payload أو producer أو transition كاملاً.

## 5. تقاطع الاختبارات مع عمليات API

سجل 97 يترك Exact mapping للعملية إلى اختبار محدد TBD / OWNER REVIEW. عائلة الاختبار على مستوى المركز لا تثبت تغطية كل عملية مفردة.

يلزم لكل عملية:
1. اختبار واحد أو أكثر يثبت الأثر الفعلي للعملية.
2. request/response fixtures وحدود الصلاحية.
3. اختبارات سلبية للرفض والتعارض والعزل.
4. التحقق من idempotency/version binding حيث ينطبق.
5. حدث تدقيق متوقع مع actor وscope وcorrelation ID.
6. evidence مرتبط بالـcommit/build والبيئة وrun ID.

لا تُربط عملية باختبار لمجرد تشابه الاسم أو وجود العملية والاختبار في المركز نفسه.

## 7. شروط إغلاق بوابة الاختبار

لا تُصنف أي حالة READY TO RUN حتى تتوفر:
- مالك اختبار ومالك مجال معتمدين.
- ربط المصدر بالوظيفة ومتطلب القبول.
- Preconditions وfixtures وخطوات قابلة للتكرار.
- Expected result وassertions واضحة.
- Environment/platform/build/version.
- Operation/Event/Approval references عند انطباقها.
- بيانات معزولة لا تمس إنتاجاً أو مؤسسة أخرى.
- run ID وlogs/screenshots/reports أو دليل مكافئ.
- مراجعة مستقلة للنتيجة.

ولا تُصنف PASS إلا بعد تنفيذ فعلي موثق ومراجعة الدليل. الحالات غير المنفذة تظل NOT EXECUTED، لا PASS ولا FAIL.

## 8. الحكم

في C01–C04 يوجد **68 معرف قبول مصدرياً**؛ 15 منها فقط تتضمن نتيجة متوقعة منفصلة في المصدر، و53 سيناريو تحتاج إلى استكمال oracle. جميع الحالات الـ68 غير منفذة. كما توجد 26 مطابقة حدث/locator دلالية، لكن 0/26 exact approved Event→Test links، وعمليات API لا تملك روابط اختبار exact معتمدة.

هذه نتيجة تدقيق جاهزية الاختبارات وليست خطة اختبار مكتملة أو إثبات جودة. يجب استكمال التعريفات واعتمادها قبل التنفيذ، ثم جمع أدلة تشغيل حقيقية. لا تُنسب النتائج المشتقة إلى المصدر الأصلي.

**لم يُعدّل كود التطبيق أو API أو قاعدة البيانات. لا تزال البرمجة غير مصرح بها حتى اكتمال المواصفات وموافقة المستخدم الصريحة المستقلة على بدء البرمجة.**
