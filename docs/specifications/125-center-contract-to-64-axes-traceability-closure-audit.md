# 125 — تدقيق ربط مسودات عقود المراكز C01–C14 بالمحاور الـ64 وحقول التتبع

**التاريخ:** 2026-11-15  
**الحالة:** DERIVED COVERAGE AUDIT / TRACEABILITY GAP / OWNER REVIEW REQUIRED / NOT APPROVED / NO IMPLEMENTATION  
**النطاق:** مراجعة الوثائق 59–70 مقابل المحاور AX-001..AX-064 وفهرس حالات الحقول 57 ومصفوفة العمليات 97/99.

## 1. النتيجة التنفيذية

توجد مسودات عقود مشتقة لكل المراكز الأربعة عشر في الوثائق 59–70، لكنها ليست متساوية في مستوى ربطها بالمحاور. الوثائق 59–63 تتضمن إشارات صريحة إلى بعض معرفات AX؛ أما الوثائق 64–70 فلا تتضمن معرفات AX صريحة في متنها. كما أن الملحق 57 يصرح بأن تحديثات الوثائق 64–71 لم تُنتج مطابقة محور-بحقل جديدة ولم تعِد احتساب إحصاءات DATA/API/AUTH/TEST.

لذلك لا يجوز الاستنتاج أن إنشاء مسودة لكل مركز أكمل تتبع المحاور أو أن المحاور الـ64 أصبحت مغطاة بعقود معتمدة. هذه الوثيقة تسجل فجوة الربط وتحدد خطة استكمالها دون اختراع روابط.

## 3. فجوة تحديث فهرس حالات الحقول 57

يسجل الملحق 57 أن:
- الحالات التفصيلية الأساسية جُمعت من تدقيقات 45–49.
- الوثائق 64–70 أضيفت لاحقاً بوصفها مسودات مشتقة للمراكز C08–C14.
- لم تُجر مطابقة محور-بحقل جديدة لهذه الوثائق.
- لم تُعد إحصاءات SCHEMA/API/AUTH/TEST بعد إضافتها.
- الربط FLD-01..26 مع AX في الوثائق 74/75 لا يغلق فجوات الحقول أو الملكية أو الاختبار.

إذن فإن فهرس 57 مفيد لتتبع تاريخ التدقيق، لكنه ليس صورة محدثة مكتملة لتغطية كل مسودات المراكز. يجب إصدار تحديث جديد بعد مراجعة محتوى كل مسودة على مستوى المحور والوظيفة والكيان والعملية والصلاحية والاختبار.

## 4. فجوة العمليات والاختبارات

- سجل 97 يحصي 201 عملية، لكن exact Test ID لكل عملية لا يزال TBD/OWNER REVIEW.
- مصفوفة 99 تربط العمليات بمحاور مرشحة عبر مطابقة أسماء وفallback للمركز؛ كل الروابط CANDIDATE وليست قرارات مالك.
- عائلات الاختبار في 80 هي مستوى مركز، ولا تثبت تغطية عملية مفردة.
- كتالوج 80 والاختبارات المضافة في 96/98/124 تصف سيناريوهات مقترحة؛ لا توجد نتائج تنفيذ مثبتة بمجرد وجود وصف.
- 106 أحداث في 100 منفصلة عن 201 عملية في 97؛ لا يجوز دمج محاور التتبع أو افتراض command-event mapping.
- سجل 98 يحصي 26 نوع موافقة مرشحاً؛ لا يثبت أن كل نوع إلزامي أو أن عملية القرار منفذة.

## 5. خطة إكمال الربط محوراً بمحور

ينبغي إنشاء سجل تغطية موحد لا يكتفي بذكر وثيقة المركز. لكل AX يجب أن يضم:

1. النص الأصلي وموضع المصدر الدقيق.
2. المتطلبات الذرية REQ مع مصدرها، أو بيان أن معرفها مشتق.
3. الوظائف FUN مع مركز مالك واحد ومراكز مساندة وقرار OWN مؤهل.
4. الشاشات SCR وعناصر UI وسلوك كل حقل وزر وحالات الواجهة.
5. كيانات DATA وحقولها وعلاقاتها وSoR وتصنيفها ونطاق tenant والاحتفاظ.
6. عمليات API وEvents مع request/response/schema/version/error/idempotency.
7. صلاحيات AUTH لكل actor/action/resource/scope/environment.
8. الموافقات APR وشرطها والعملية المحمية وبصمة المورد وسياسة الاستقلال.
9. اختبارات TEST ومعيار القبول والبيانات والبيئة ونتيجة التنفيذ.
10. أدلة EVIDENCE قابلة للتحقق، أو حالة صريحة NOT EXECUTED / MISSING.
11. التعارضات والافتراضات والقرارات المفتوحة مع المالك المسؤول.

## 7. شروط إغلاق GAP-044 وGAP-020 وGAP-027

- GAP-044: ربط جميع المحاور بالحقول المطلوبة ومراجعة المالك ومصدر كل حقل.
- GAP-020: اكتمال ownership/operation/event/test linkage وعدم وجود عمليات بلا مالك أو اختبار أو N/A مبرر.
- GAP-027: اكتمال الربط المصدرّي الدقيق لكل عقد ومخطط وعملية وعدم الاعتماد على locator مركز عام.
- تدقيق 94 و99 يجب أن يعاد بعد اكتمال الربط، مع عدم اعتبار وجود IDs وحده كافياً.
- يلزم اعتماد مالكي المراكز قبل ترقية أي حالة إلى APPROVED.
