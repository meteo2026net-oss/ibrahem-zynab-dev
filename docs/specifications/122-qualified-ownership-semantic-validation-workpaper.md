# 122 — حزمة التحقق الدلالي من إحالات OWN للعمليات الـ139

**التاريخ:** 2026-11-15  
**الحالة:** OWNERSHIP SEMANTIC VALIDATION WORKPAPER / DERIVED / OWNER REVIEW REQUIRED / NOT APPROVED / NO IMPLEMENTATION  
**النطاق:** العمليات الـ139 التي تحمل إحالة OWN36/OWN72 مؤهلة شكلياً في سجل 97.  
**المراجع:** 36 و72 و82 و97 و111 و112 و113 و120 و121.

## 1. الغرض والنتيجة

أثبت تدقيق 111 أن 139 من أصل 201 عملية تحتوي إحالة OWN مؤهلة من حيث الصياغة والوجود في namespace 82. لكنه نص صراحة على أن وجود المعرف لا يثبت أن نطاق القرار يغطي العملية، أو أن القرار معتمد، أو أن مالك المجال وافق عليه.

لذلك لا تُعامل الـ139 عملية على أنها «مغلقة الملكية». هذه الحزمة تحول نتيجة التدقيق الشكلي إلى قائمة تحقق دلالية إلزامية قبل اعتبار أي إحالة صالحة للاعتماد.

| المقياس | العدد | الدلالة |
|---|---:|---|
| عمليات سجل 97 | 201 | كامل سجل العمليات |
| إحالات OWN مؤهلة شكلياً | 139 | مرجع موجود وصيغته مؤهلة فقط |
| عمليات بلا إحالة OWN مفردة | 62 | موثقة تفصيلاً في 121 |
| معرفات OWN المؤهلة المستخدمة | 14 | تحتاج مراجعة النطاق لكل استخدام |
| إحالات مختصرة غير مؤهلة | 0 | نجاح تنسيقي، لا اعتماد ملكية |
| عمليات ذات اختبار Exact ID | 0/201 | فجوة مستقلة لا تغلقها إحالة OWN |

## 3. اختبار صلاحية كل إحالة — لا يكفي تطابق المعرف

يجب إكمال سجل مراجعة لكل زوج (Operation ID, OWN ID)، وليس لكل معرف OWN مرة واحدة فقط:

1. **Exact scope:** هل يذكر القرار العملية أو فئة العمليات أو الكيان الذي تنتمي إليه بوضوح؟ إذا كان الربط استنتاجاً، يسجل CANDIDATE لا APPROVED.
2. **Decision status:** هل القرار APPROVED فعلاً؟ لا تكفي حالة DRAFT أو PROPOSED أو OPEN أو وجود المعرف في namespace.
3. **Decision authority:** هل المالك والموافق وتاريخ القرار وإصداره مسجلون؟
4. **Domain ownership:** هل حُدد Domain Owner وDomain SoR؟ وهل يظل مصدر حقيقة المجال لدى المركز الصحيح؟
5. **Shared-service boundary:** هل يفصل القرار بين مالك المجال ومالك تنفيذ SH، دون نقل حقيقة المجال إلى الخدمة المشتركة؟
6. **Operation semantics:** هل العملية Command أو Query أو Job أو Approval decision؟ وهل يتسق القرار مع نوعها وأثرها؟
7. **Data scope:** هل حُدد tenant/organization/workspace/project/environment scope والكيانات والحقول المتأثرة؟
8. **Security and audit:** هل عُينت صلاحيات الفاعل والمورد والنطاق، ومسار الموافقة، ومرجع التدقيق؟
9. **Test linkage:** هل يوجد اختبار قبول مفرد أو استثناء مبرر وموافق عليه؟ لا يُستبدل ذلك بعائلة اختبار عامة.
10. **Change control:** هل يرتبط القبول بإصدار القرار ونسخة العقد؟ وهل يعاد فتح المراجعة عند تغير العملية أو القرار؟

## 4. حالات المراجعة المسموح بها

| الحالة | معناها | هل تغلق الملكية؟ |
|---|---|---|
| FORMAT-VALID | صيغة OWN مؤهلة والمعرف موجود | لا |
| SCOPE-CANDIDATE | توجد قرائن دلالية لكن النطاق غير معتمد | لا |
| OWNER-REVIEW | ينتظر مراجعة مالك المجال والخدمة | لا |
| APPROVED-EXACT | المالك وافق على انطباق القرار المحدد على العملية المحددة | نعم، بعد استكمال بقية شروط الإغلاق |
| APPROVED-EXCEPTION | استثناء/N/A مبرر وموافق عليه | نعم، في حدود الاستثناء |
| REJECTED-MISMATCH | القرار لا يغطي العملية أو يتعارض مع حدودها | لا؛ يلزم قرار صحيح |
| SUPERSEDED | القرار استبدل بإصدار أحدث مع حفظ التاريخ | لا؛ يجب الإشارة إلى القرار البديل |

لا يجوز تحويل FORMAT-VALID أو SCOPE-CANDIDATE إلى APPROVED-EXACT آلياً.

## 5. سجل المراجعة المطلوب لكل عملية

يجب أن يحتوي سجل الاعتماد النهائي على الحقول التالية، مع إبقاء TBD حيث لا يوجد دليل:

| الحقل | المطلوب |
|---|---|
| Operation ID / name | كما في سجل 97 دون إعادة تسمية |
| Center | المركز الحالي؛ لا تنقل العملية دون قرار |
| Qualified OWN ID | المرجع الحالي كما هو |
| OWN decision version | إصدار القرار أو hash/locator |
| Decision status | حالة الاعتماد الفعلية |
| Domain Owner | المالك المعتمد |
| API Owner | مالك عقد العملية |
| Domain SoR | مصدر الحقيقة للكيان/الحقيقة |
| Shared Service role | منفذ/مستهلك/مراقب، لا مالك حقيقة المجال افتراضياً |
| Entity/field scope | الكيانات والحقول والنطاق المتأثر |
| Approval requirement | إلزامي/مشروط/N/A مع السياسة |
| Exact Test ID | معرف أصلي أو معرف مقترح معتمد |
| Evidence | قرار المالك ومحضر المراجعة ودليل الاختبار بعد التنفيذ |
| Reviewer/date | المراجع وتاريخ المراجعة |

## 6. ارتباط هذه الحزمة بالفجوات القائمة

- **121:** يعالج الـ62 عملية التي لا تحمل إحالة OWN مؤهلة. لا تستبدل هذه الحزمة قرارات المالكين في 121.
- **112:** يثبت أن 0/201 عملية لها Exact Test ID في سجل 97. إحالة OWN صحيحة لا تعني وجود اختبار.
- **113:** يربط إغلاق الملكية بإغلاق API/Event/Approval، ولا يسمح باستخدام محور لتغطية محور آخر.
- **116–119:** دورة الموافقات منفصلة عن ملكية العملية؛ SH-03 منسق workflow مقترح وليس Domain Decision Owner.
- **120:** يجب أن يتطابق قرار الملكية مع SoR والحقول والنطاق والاحتفاظ وتصنيف البيانات، لا اسم العملية وحده.

## 7. بوابة إغلاق إحالات الـ139

لا تُعلن الإحالات الـ139 مغلقة إلا عند تحقق الشروط التالية لكل عملية:

- [ ] تحقق Exact scope من نص قرار OWN وإصداره.
- [ ] اعتماد مالك المجال ومالك عقد API عند اختلافهما.
- [ ] تعيين Domain SoR ومنع وجود مصدرين قابلين للكتابة للحقيقة نفسها.
- [ ] اعتماد حد الخدمة المشتركة ودورها التشغيلي.
- [ ] حسم tenant/workspace/project/environment والضوابط الأمنية.
- [ ] ربط اختبار قبول مفرد أو استثناء موثق وموافق عليه.
- [ ] حفظ دليل الاعتماد والتاريخ والإصدار.
- [ ] مراجعة أي تضارب مع عملية أو مركز آخر دون تغيير تاريخ المصدر.

**النتيجة الحالية:** 139 FORMAT-VALID فقط وفق تدقيق 111؛ لا يوجد في الأدلة التي راجعتها ما يسمح بإعلانها APPROVED-EXACT جميعاً. لا تنشئ هذه الحزمة APIs أو schemas أو migrations أو كوداً، ولا تنفذ اختبارات، ولا تعتمد قرارات نيابة عن المالكين. تظل بوابة المواصفات وموافقة البرمجة المستقلة قائمة.
