## 4. مراجعة اتساق العقود السبعة

### C08 — الملفات والوسائط
حد الملكية متسق مبدئياً: C08 يملك سجل الأصل وعلاقاته؛ SH-06 يملك سجلات التخزين والمعالجة التشغيلية. فجوات الإغلاق: upload session/receipt، حدود الحجم والصيغ، فحص malware، quarantine visibility، مفاتيح التشفير ومناطق البيانات، مشاركة الروابط، legal hold، الحذف والمشتقات، idempotency وcache/ACL invalidation. لا يعتمد حذف نهائي أو معالجة آلية قبل تحديد سياسة الاحتفاظ ومالك الموافقة والنطاق والأدلة.

### C09 — التكاملات
يفصل الحد المقترح تكامل المجال عن runtime الموصل والأسرار، ولا يخزن C09 token خاماً. فجوات الإغلاق: قائمة موصلات الإصدار الأول، OAuth scopes/redirects، SSRF allowlist، webhook signature/replay protection، مزامنة الكتابة والتعارض، idempotency، data residency، تكلفة المزود وإلغاء الاعتمادات. لا تنشأ موصلات أو صلاحيات إنتاجية من مجرد وجود العمليات المقترحة.

### C10 — الأمن والحوكمة
يملك C10 السياسات والتقييمات والاستثناءات؛ وتبقى SH-01/02/03/04 خدمات الهوية والتفويض والموافقة والتدقيق. تعارض Zero Trust باقٍ دون حسم: الفصل 158.7 يعرضه إلزامياً، بينما 158.9 وDEC-SEC-010 يعرضانه مقترحاً. يلزم اعتماد RBAC/ABAC وthreat model وتصنيف البيانات وretention والاستثناءات وضوابط الوكلاء ومراجعة مستقلة.

### C11 — البناء والإصدارات والنشر
فصل release lifecycle في C11 عن resource version/change-set في SH-10 صحيح وضروري. تعارض ملكية validateBuildConfiguration بين C05 وC11 لا يزال مفتوحاً. يلزم اعتماد CI runners وartifact registry وتوقيع artifacts وSBOM وrelease channels وموافقات المتاجر وrollback/migration safety وSLO وRTO/RPO والميزانية.

### C12 — المعرفة والتوثيق
C12 يملك الوثيقة المعرفية؛ C08/SH-06 يملكان آلية الملف؛ SH-16 يملك الفهرسة ومشتقاتها؛ SH-07 البحث. فجوات الإغلاق: canonical document schema وOCR/AI providers وsource licensing وretention/deletion propagation وACL freshness وSLA لإبطال الفهرس وpublication workflow. يجب منع تسرب مقتطفات البحث بعد سحب الصلاحية أو حذف المصدر.

### C13 — الإعدادات
C13/SH-12 يديران آلية الإعدادات والتوريث؛ مالك كل مجال يظل صاحب معنى الإعداد وقواعد تطبيقه. فجوات الإغلاق: precedence عند التعارض وتعريفات المفاتيح والنطاقات وسياسات الأسرار وchange approval وexport/import وrollback والتدقيق. أي إعداد حساس يمر بسياسة C10 ومالك المفتاح؛ لا يملك الوكيل تغيير السياسات أو الأسرار.

### C14 — لوحة التحكم
C14 طبقة عرض وإسقاط لا Domain SoR، وهذا متسق مع التسوية الأحدث التي تعتمد C14 لوحة التحكم. فجوات الإغلاق: تعريف KPI ومصدره وfreshness thresholds وcache invalidation وprojection versioning وtenant isolation وredaction وreporting/export permissions. لا يجوز عرض نتيجة قديمة كحالة آنية أو دمج بيانات مؤسسات مختلفة.

## 5. فجوات المصدر والتتبع

1. B08–B14 غير مستعادة: يلزم استرجاع التصدير/المصدر الأصلي قبل إنشاء source screen/function/test registries لهذه المراكز.
2. لا معرفات أصلية مستنتجة: C08-DRAFT-AT وما شابهها معرفات محلية مشتقة وليست معرفات مصدرية.
3. العمليات الـ81 مرشحة ضمن workpapers 126–131؛ لا تعامل على أنها APIs منشورة أو معتمدة، ولا تجمع مع 201 قبل إزالة التداخل والتحقق من المصدر.
4. الأحداث الـ55 موصوفة بدرجات استرداد مختلفة؛ لا exact event names ولا exact Event→Test ID مثبت في هذه الحزم.
5. الموافقات الـ14 أنواع مرشحة تحتاج Decision Owner وApproval Policy وربطاً بـ26 موافقة في سجل 98 دون افتراض equivalence.
6. الاختبارات الـ124 SPECIFIED / NOT RUN؛ لا يوجد دليل تشغيل أو نجاح.
7. الكيانات والجداول في العقود 64–70 PROPOSED؛ لا تنشئ schema أو migrations.
8. قرارات Zero Trust وعتبات الميزانية وnamespaces وRTO/RPO وملاك registry/secret/storage لا تزال مفتوحة أو متعارضة.

## 6. بوابة الإغلاق المطلوبة لكل مركز

لا يعتبر أي مركز جاهزاً للبرمجة قبل توفر: النص الأصلي أو قرار صريح بتبني عقد مشتق بديلاً عنه؛ مالك مجال ومالك خدمة مشتركة معتمدين وتوقيع حدود SoR؛ تعريف العمليات ومدخلاتها ومخرجاتها وأخطائها وtenant scope وidempotency وaudit وpermission؛ تعريف الأحداث وschema/version/producer/consumer/correlation/retention/retry؛ تعريف الموافقات وDecision Owner وseparation of duties؛ ربط كل وظيفة/عملية/حدث/موافقة باختبار قبول ونتيجة متوقعة ودليل؛ اعتماد قرارات الخصوصية والأمن والتكلفة والتشغيل؛ ومراجعة وتوقيع مالك المركز ثم اجتياز بوابة المواصفات الموحدة. هذا لا يمنح وحده موافقة بدء البرمجة.
