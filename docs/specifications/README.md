## تعريف حالات المعلومات

- **APPROVED:** قرار اعتمده المستخدم صراحةً.
- **PROPOSED:** توصية لم تُعتمد بعد.
- **PENDING_USER:** يحتاج قراراً من المستخدم.
- **PENDING_REVIEW:** يحتاج مراجعة فنية أو أمنية.
- **CONDITIONAL:** معتمد بشرط أو ضمن حدود محددة.
- **DEFERRED:** مؤجل إلى مرحلة لاحقة.
- **OPEN:** لم يُحسم.
- **RECOVERED_SUMMARY:** استعيد كملخص، لا كنص تفصيلي كامل.
- **RECOVERED_DETAILED:** توفرت تفاصيل موسعة في سياق العمل، لكنها تحتاج إدراجاً ومراجعة نهائية.
- **NOT_RECOVERED:** التفاصيل غير متاحة حالياً ويجب استعادتها أو استكمالها قبل اعتبار المواصفات مكتملة.

## قاعدة عدم الادعاء بالاكتمال

تسلسل النقاشات السابق وصل إلى الفصل 163، لكن أرقام الفصول وحدها لا تعني أن نصوصها الكاملة موجودة في هذه الحزمة. لذلك نستخدم سجل التغطية في الملف 05 لتحديد ما استعيد وما يحتاج استكمالاً. لا تُعامل هذه النسخة على أنها اعتماد نهائي أو تصريح بالبرمجة.

## معيار اكتمال أي مركز

لا يُعتبر المركز موثقاً بما يكفي للتنفيذ إلا إذا احتوى، على الأقل، على:
1. الهدف وحدود النطاق.
2. قائمة الشاشات ومعرف ثابت لكل شاشة.
3. الوظائف ومعرف ثابت لكل وظيفة.
4. مدخلات كل وظيفة ومخرجاتها وحالات الفشل.
5. الأدوار والصلاحيات.
6. الكيانات والحقول والعلاقات التي يملكها المركز.
7. عقود API أو الأحداث المطلوبة.
8. قواعد التحقق والأمن والخصوصية.
9. اختبارات قبول قابلة للتنفيذ وأدلة نجاح.
10. الاعتماديات والمخاطر والقرارات المفتوحة.
