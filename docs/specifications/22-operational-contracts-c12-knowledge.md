# 22 — العقود التشغيلية الأولية لمركز المعرفة والتوثيق C12

**الحالة:** DRAFT / RECOVERED SCREEN MAP + DERIVED CONTRACTS  
**المصدر:** الفصل 152 المستعاد والملف 18، مع مطابقة قائمة الشاشات العشرين في الملف 02.  
**تنبيه:** أسماء الشاشات مستعادة، أما تفاصيل العقود التشغيلية فهي تفصيل مقترح للمراجعة وليست اعتماداً أو إثبات تنفيذ.

## 1. المبادئ والحدود

- C12 يملك الوثائق والمعرفة والفهرسة المرجعية وسجل مصدر المعلومة، لكنه لا يصبح مالكاً للمتطلبات أو الكود أو البيانات أو نتائج الاختبار الأصلية.
- يجب أن يحمل كل عنصر معرفاً ومصدراً وإصداراً ومالكاً وتصنيفاً وحالة اعتماد وتاريخ صلاحية/مراجعة عند الحاجة.
- يجب تمييز المحتوى إلى: حقيقة موثقة، قرار معتمد، اقتراح، افتراض، استنتاج، أو مادة غير متحقق منها.
- لا يعتمد مخرجات AI تلقائياً، ولا يسمح لمحتوى مستورد بأن يتحول إلى تعليمات تشغيلية موثوقة.
- كل بحث أو تصدير أو مشاركة يخضع لصلاحيات الوثيقة ومصدرها ونطاق المؤسسة/المشروع.

## 3. وظائف مشتركة لازمة

1. مصدر وسجل منشأ لكل وثيقة ومقتطف ومعلومة مستخرجة.
2. إصدار immutable للوثائق المعتمدة مع diff قابل للمراجعة.
3. ربط ثنائي الاتجاه بين المعرفة والمتطلبات والوظائف والشاشات والبيانات وAPI والكود والاختبارات والقرارات والإصدارات.
4. بحث نصي ومتجهي يحترم صلاحيات المصدر قبل عرض النتائج أو استخدامها في سياق AI.
5. سياسة تصنيف واحتفاظ وحذف وتصدير مركزية، دون اختراع تصنيفات محلية غير معتمدة.
6. تمييز الثقة ومصدر OCR/AI وعدم تحويل الاستنتاج إلى حقيقة.
7. مراجعة بشرية للمخرجات التي ستؤثر في مواصفات معتمدة أو قرارات.
8. عزل فهارس المؤسسة والمشروع أو فرض security filters لا يمكن تجاوزها.
9. حذف/إخفاء/تصحيح معلومات قديمة وفق سجل provenance دون إتلاف تاريخ القرارات المعتمدة.
10. سجل تدقيق للقراءة الحساسة والتصدير والمشاركة والتغيير والاعتماد.

## 4. الكيانات المقترحة

تحتاج المطابقة مع الفصل الأصلي قبل اعتماد أسماء الجداول، لكن نطاق البيانات يتطلب على الأقل مفاهيم: documents، document_versions، document_sources، source_fragments، citations، knowledge_items، knowledge_links، decision_records، review_requests، approvals، search_indexes، extraction_jobs، export_jobs، share_grants، retention_policies، classification_labels، audit_references.

هذه أسماء مفاهيمية وليست أسماء جداول معتمدة.

## 5. اختبارات القبول

يجب استعادة النص الأصلي لحالات C12 من الفصل 152؛ لم يُستعد في المواد الحالية ترقيم كامل وموثوق لحالات C12. الاختبارات الأساسية المطلوب صياغتها واعتمادها:
- منع البحث أو الاسترجاع عبر حدود المؤسسات والمشاريع.
- رفض عرض وثيقة بلا صلاحية حتى لو ظهرت في نتائج فهرس متجهي.
- كل إجابة معرفية تستشهد بمصادر مسموح بها وتوضح عدم اليقين.
- اكتشاف التعليمات الخبيثة داخل المستندات كبيانات غير موثوقة.
- عدم اعتماد استخراج OCR/AI دون مراجعة عند الحاجة.
- ربط تقرير اختبار بإصدار build الصحيح.
- منع تعديل ADR معتمد دون إصدار جديد وسجل supersedes.
- منع التصدير من تسريب الأسرار أو المحتوى المحظور.
- تطبيق سياسة الاحتفاظ والحذف مع سجل إثبات.
- إظهار مصدر وتاريخ وإصدار كل معلومة معروضة.

هذه اختبارات استكمال مقترحة وليست نتائج تشغيل فعلية.

## 6. الفجوات المفتوحة

- استعادة أسماء الكيانات الأصلية وحقولها الكاملة.
- استعادة معرفات واختبارات C12 الأصلية إن وجدت.
- مطابقة مستويات تصنيف البيانات مع قرار مركزي واحد.
- تحديد محرك الفهرسة والبحث كاختيار تقني منفصل.
- تحديد سياسة الاحتفاظ والحذف بحسب فئة البيانات والولاية القانونية.
- تحديد صلاحيات مشاركة المعرفة بين المؤسسات.
- اعتماد schema لعقود citations وprovenance وconfidence.
- ربط وظائف C12 بمصفوفة التتبع العامة.

**الخلاصة:** أصبح لدينا عقد تشغيلي أولي لكل شاشة من شاشات C12 العشرين، لكنه لا يغلق GAP-011 قبل استكمال الكيانات والعقود والاختبارات ومراجع المصدر واعتماد مالك المركز.
