# 32 — العقود التفصيلية الأولية للخدمات المشتركة SH-09..SH-16

**الحالة:** DRAFT / PROPOSED CONTRACT BASELINE — بانتظار مراجعة المالك واعتماد القرارات المفتوحة  
**التاريخ:** 2026-11-10  
**النطاق:** استكمال البطاقات التعاقدية للخدمات SH-09 إلى SH-16 دون تغيير قائمة الخدمات التاريخية أو الادعاء بأن هذه العقود مستعادة حرفياً من المصدر.

## 1. خلاصة الأدلة وحدودها

1. الفصل 132.6 في الأرشيف يسرد الخدمات SH-01..SH-16 تحت وصف «الخدمات المقترحة».
2. النص التفصيلي في 132.6.1–132.6.8 يشرح الخدمات الثماني الأولى. أما SH-09..SH-16 فتظهر في القائمة بالاسم والمسؤولية المختصرة، ولا يقدم المقتطف المصدر عقداً تفصيلياً مستقلاً لها.
3. الفصل 155.13 يسجل الفصل 157 بعنوان «توحيد المكونات والخدمات المشتركة» وحالته «مطلوب»، ولا يورد متن الفصل.
4. تمت مراجعة ملفات المصدر السبعة المحفوظة في `docs/source-conversations`. لم يظهر متن مستقل للفصل 157؛ ظهرت إشارة 155.13 إليه في الأرشيفات التي تحتوي هذا المقطع. هذا يثبت حدود الملفات المفحوصة فقط، ولا ينفي وجود مصدر آخر غير محفوظ.
5. لذلك فالحقول والعمليات والمخططات والاختبارات أدناه **مقترحات هندسية قابلة للمراجعة** مستندة إلى مسؤوليات الخدمات والقرارات العامة الموجودة، وليست نصاً تاريخياً مستعاداً أو اعتماداً نهائياً.

## 2. قواعد العقد الموحدة

كل عملية بين خدمة وأخرى يجب أن تحمل، بحسب نوع العملية، الحقول المنطقية التالية:

- `requestId`: معرف فريد للطلب.
- `correlationId`: ربط العملية بسلسلة العمل الأصلية.
- `actor`: مرجع الفاعل البشري أو الوكيل أو الخدمة.
- `scope`: المؤسسة ومساحة العمل والمشروع والبيئة عند انطباقها.
- `contractVersion`: إصدار مخطط العقد.
- `idempotencyKey`: مطلوب للعمليات التي قد يعاد إرسالها ويجب ألا تكرر أثراً.
- `occurredAt`: وقت الحدث بصيغة زمنية موحدة، مع توثيق مصدر الساعة.
- `dataClassification`: تصنيف البيانات عندما تتضمن الحمولة بيانات غير عامة.

**قواعد ملزمة من خط الأساس المعماري:** إعادة التحقق من الهوية والصلاحية لدى الخدمة المالكة؛ عدم الثقة في scope المرسل وحده؛ عدم الوصول المباشر غير المنضبط إلى جداول مركز آخر؛ عدم تسجيل الأسرار؛ وتسجيل العمليات الحساسة في سجل التدقيق.

**قواعد تحتاج قراراً تقنياً لاحقاً:** معيار تسمية المسارات، تقنية النقل، وسيط الأحداث، مخطط الترميز، سياسة الاحتفاظ الافتراضية، وحدود التوافق بين الإصدارات.

## 3. بطاقة العقد المقترحة لكل خدمة

### SH-09 — Event Service | خدمة الأحداث

**المسؤولية:** نقل أحداث المجال والتكامل بين الخدمات مع حفظ إمكانية التتبع وإعادة المعالجة. لا تملك هذه الخدمة حقيقة بيانات المجال ولا تستبدل مالك المجال.

- **الملكية المقترحة:** تملك سجلات النشر والاستلام والاشتراكات ومحاولات التسليم؛ مصدر الحدث ومحتواه الدلالي يظل لدى الخدمة/المركز المنتج.
- **المستهلكون المرشحون:** الخدمات المشتركة والمراكز التي تتبادل أحداثاً، خصوصاً المهام والإشعارات والتدقيق والمراقبة.
- **عمليات مرشحة:** `publishEvent`، `registerSubscription`، `pauseSubscription`، `replayDelivery`، `getDeliveryStatus`، `deadLetterReview`.
- **الحمولة الدنيا المقترحة:** `eventId`، `eventType`، `eventVersion`، `producer`، `occurredAt`، `correlationId`، `scope`، `dataClassification`، `payloadRef` أو payload محدود.
- **ضوابط:** نمط outbox/inbox عند الحاجة؛ deduplication بواسطة eventId؛ التحقق من schema والإصدار؛ عدم افتراض ترتيب عالمي؛ تحديد ترتيب محلي فقط حيث يطلبه عقد المجال؛ فصل dead-letter عن إعادة الإرسال؛ وعدم بث بيانات حساسة غير لازمة.
- **حالات التسليم المقترحة:** Pending، Published، Delivered، RetryScheduled، DeadLetter، Suppressed. لا تعني Delivered أن المستهلك أكمل أثر المجال إلا إذا أكد عقده ذلك.
- **أخطاء:** invalid schema، unknown event type، unauthorized producer، duplicate event، consumer unavailable، retry limit reached.
- **اختبارات قبول مقترحة:** EVT-01 تكرار eventId لا يكرر الأثر؛ EVT-02 تعطل المستهلك ينتج حالة قابلة للاستعادة ولا يفقد مرجع الحدث؛ EVT-03 حدث بإصدار غير مدعوم يرفض أو يعزل وفق سياسة توافق معلنة؛ EVT-04 لا تتسرب بيانات سرية إلى السجل أو dead-letter.

### SH-10 — Version Service | خدمة الإصدارات

**المسؤولية:** إدارة تاريخ إصدارات الموارد ومجموعات التغيير واللقطات والمقارنات، دون امتلاك منطق محتوى الموارد.

- **الملكية المقترحة:** تملك metadata الخاصة بالإصدار والعلاقات ومجموعات التغيير واللقطات المرجعية؛ يبقى محتوى المورد لدى مركزه أو خدمة تخزينه المالكة.
- **المستهلكون المرشحون:** C01 وC02 وC03 وC04 وC05 وC08 وC11 وC12، مع التحقق من المستهلكين الفعليين أثناء مطابقة المراكز.
- **عمليات مرشحة:** `createVersion`، `getVersion`، `compareVersions`، `createChangeSet`، `validateChangeSet`، `createSnapshot`، `tagVersion`، `restoreReference`.
- **مدخلات:** resourceType/id، baseVersion، contentRef أو contentHash، changeSet، actor، scope، reason، approvalRef عند الحاجة.
- **مخرجات:** versionId، parentVersion، contentRef/hash، author، createdAt، changeSetRef، approvalRef، integrity status.
- **ضوابط:** منع الكتابة فوق إصدار منشور؛ كشف التعارضات قبل الدمج؛ ربط الموافقة ببصمة المورد والإصدار؛ التراجع ينشئ إصداراً جديداً ولا يمحو التاريخ؛ وعدم افتراض أن كل الموارد تدعم branching أو merge.
- **أخطاء:** stale base version، merge conflict، immutable version، missing content reference، approval mismatch.
- **اختبارات:** VER-01 تعديل نسخة قديمة لا يستبدل النسخة الأحدث؛ VER-02 المقارنة تعرض الفروق ومراجع المصدر؛ VER-03 الاستعادة تحفظ التاريخ وتنشئ إصداراً جديداً؛ VER-04 لا ينجح اعتماد تغيرت بصمته بعد الموافقة.

### SH-11 — Cost Service | خدمة التكاليف والميزانيات

**المسؤولية:** تجميع سجلات الاستهلاك والتكلفة ومقارنتها بميزانيات النطاق، دون اختراع أسعار أو قواعد فوترة غير معتمدة.

- **الملكية المقترحة:** تملك سجلات الاستهلاك المحاسبية المجمعة والميزانيات والتنبيهات والتقديرات؛ مصدر القياس/السعر الأصلي يظل موثقاً لدى مزوده أو المجال المسؤول.
- **المستهلكون المرشحون:** C06 وC13 وC14 وخدمات AI والبناء والتخزين والتكامل بحسب ما تثبته مصفوفة المستهلكين.
- **عمليات مرشحة:** `ingestUsage`، `recordCost`، `estimateCost`، `createBudget`، `evaluateBudget`، `getCostBreakdown`، `closeCostPeriod`.
- **مدخلات:** provider، meter، quantity، unit، rateRef، currency، scope، usagePeriod، sourceRef، confidence/estimate flag.
- **مخرجات:** normalized usage record، cost item، budget status، forecast، source lineage.
- **ضوابط:** فصل التقديري عن الفعلي؛ عدم جمع عملات مختلفة دون سعر تحويل ومصدر وتاريخ؛ حفظ وحدة القياس؛ منع التكرار؛ وعدم تحويل عتبات 50/75/90/100 المذكورة في الفصل 141 إلى سياسة معتمدة تلقائياً.
- **قرارات مفتوحة:** العملة الأساسية، مصادر الأسعار، التقريب، سياسة الفترات، الضرائب، الفوترة، العتبات، ومن يملك اعتماد الميزانية.
- **أخطاء:** unknown meter، missing rate source، currency mismatch، duplicate usage، closed period، budget scope unauthorized.
- **اختبارات:** COST-01 لا تخلط التقديرات مع الفعلي؛ COST-02 سجل الاستهلاك المكرر لا يحتسب مرتين؛ COST-03 كل مبلغ قابل للتتبع إلى مصدر وسعر ووحدة وفترة؛ COST-04 لا تطبق عتبة غير معتمدة كمنع تلقائي.

### SH-12 — Configuration Service | خدمة الإعدادات

**المسؤولية:** إدارة تعريفات الإعدادات وقيمها ومخططاتها ووراثتها وإصداراتها على النطاقات المختلفة.

- **الملكية المقترحة:** تملك سجل تعريفات الإعدادات والقيم العامة للمنصة وتاريخ التغييرات؛ الإعدادات الدلالية الخاصة بالمجال تبقى تحت مالك المجال مع استخدام آلية مشتركة.
- **المستهلكون المرشحون:** جميع المراكز والخدمات، مع صلاحيات تختلف حسب نطاق الإعداد.
- **عمليات مرشحة:** `defineSetting`، `getEffectiveConfig`، `validateConfig`، `updateConfig`، `previewInheritance`، `rollbackConfigVersion`.
- **مدخلات:** key، schemaRef، value، scope، precedence context، actor، reason، expectedVersion.
- **مخرجات:** effective value أو masked value، source scope، version، validation result، provenance.
- **ضوابط:** تحقق schema قبل الحفظ؛ كشف مصدر القيمة الموروثة؛ منع تجاوز إعداد أعلى أولوية دون صلاحية؛ الأسرار تحفظ في Secret Manager ولا تعاد كنص؛ وتغيير الإعداد الحساس قد يتطلب موافقة.
- **ترتيب الوراثة:** لا يثبت نهائياً في هذه الوثيقة. يجب اعتماده صراحةً بين إعدادات المنصة والمؤسسة ومساحة العمل والمشروع والبيئة والمستخدم، مع تعريف الاستثناءات.
- **أخطاء:** schema validation failed، precedence conflict، immutable setting، secret reference missing، stale version.
- **اختبارات:** CFG-01 القيمة غير الصالحة ترفض؛ CFG-02 تظهر القيمة الفعالة ومصدر وراثتها؛ CFG-03 لا تعاد قيمة السر الخام؛ CFG-04 التراجع ينشئ إصداراً موثقاً ولا يمحو سجل التغيير.

### SH-13 — Integration Service | خدمة التكاملات

**المسؤولية:** إدارة تعريفات الموصلات والاتصالات ومراجع الأسرار وحالة الربط والعقود مع المزودين، دون امتلاك حسابات المزود الخارجية.

- **الملكية المقترحة:** تملك connection metadata وconnector lifecycle وhealth references؛ الأسرار الفعلية تملكها خدمة أسرار مستقلة/موفر معتمد، ولا تخزن في manifest أو سجلات عادية.
- **المستهلكون المرشحون:** C09 أساساً، إضافة إلى المراكز التي تطلب تكاملاً معتمداً.
- **عمليات مرشحة:** `registerConnector`، `validateManifest`، `createConnection`، `testConnection`، `rotateCredentialReference`، `disableConnection`، `revokeConnection`.
- **مدخلات:** connectorId/version، manifest، requestedCapabilities، permissionGrant، secretRef، providerAccountRef، scope.
- **مخرجات:** connectionId، lifecycleState، grantedCapabilities، healthRef، lastValidatedAt.
- **ضوابط:** allowlist للقدرات؛ أقل صلاحية؛ عزل التنفيذ؛ قيود خروج الشبكة؛ التحقق من redirect/callback؛ عدم تمرير أسرار إلى الوكلاء أو السجلات؛ الموافقة قبل التفعيل عالي الأثر؛ وإمكانية الإبطال الفوري.
- **قرارات مفتوحة:** صيغة manifest النهائية، نموذج sandbox، سياسة network egress، آلية توقيع الإضافات/الموصلات، ومصفوفة توافق الإصدارات.
- **أخطاء:** manifest invalid، capability denied، secret reference expired، provider unavailable، callback mismatch، connection revoked.
- **اختبارات:** INT-01 موصل يطلب قدرة غير ممنوحة يرفض؛ INT-02 إبطال الاتصال يمنع الاستدعاءات اللاحقة؛ INT-03 لا يظهر السر في استجابة أو log؛ INT-04 لا ينجح الاختبار إذا فشل تحقق هوية المزود.

### SH-14 — Monitoring Service | خدمة المراقبة

**المسؤولية:** تجميع مؤشرات صحة الخدمات والقياسات والتنبيهات التشغيلية وربطها بالحوادث، دون امتلاك بيانات الأعمال التي تنتجها المراكز.

- **الملكية المقترحة:** تملك مؤشرات التشغيل ونتائج الفحوص والتنبيهات ومراجع الحوادث؛ الخدمة المراقبة تظل مالكة لسجلات المجال.
- **المستهلكون المرشحون:** L9/L10 وC14 وجميع الخدمات المنتجة لمؤشرات التشغيل.
- **عمليات مرشحة:** `publishHealth`، `ingestMetric`، `queryServiceHealth`، `evaluateAlertRule`، `openIncidentRef`، `acknowledgeAlert`، `resolveAlert`.
- **مدخلات:** serviceId، component، metricName، value، unit، timestamp، environment، region، correlationId، health state.
- **مخرجات:** health snapshot، metric series ref، alert state، incident reference، freshness indicator.
- **ضوابط:** فصل health عن readiness؛ تعريف مصدر القياس ووقت آخر تحديث؛ منع تضخيم العدادات؛ تقييد الوصول للمقاييس الحساسة؛ وعدم اعتبار غياب القياس دليلاً على سلامة الخدمة.
- **قرارات مفتوحة:** SLI/SLO، sampling، retention، alert routing، تصنيف شدة الحوادث، ومن يملك إغلاق الحادث.
- **أخطاء:** invalid metric schema، stale telemetry، unauthorized producer، duplicate sample، alert rule invalid.
- **اختبارات:** MON-01 غياب القياس يظهر Unknown/Stale لا Healthy؛ MON-02 التنبيه مرتبط بمصدر وقاعدة؛ MON-03 لا تكرر العينة نفسها عند إعادة الإرسال؛ MON-04 صلاحية المستخدم تحدد تفاصيل ما يراه.

### SH-15 — Backup Service | خدمة النسخ الاحتياطي

**المسؤولية:** تنسيق النسخ والاستعادة للبيانات والأصول والإعدادات والوثائق وفق حدود الملكية والاتساق، مع أدلة تحقق.

- **الملكية المقترحة:** تملك كتالوج مهام النسخ والاستعادة والبيانات الوصفية ومراجع الأدلة؛ كل مركز/خدمة يظل مالكاً لبياناته ومصدر الحقيقة.
- **المستهلكون المرشحون:** جميع الخدمات المالكة لبيانات قابلة للاستعادة، مع تنسيق التشغيل ضمن L9/L10.
- **عمليات مرشحة:** `createBackupPlan`، `startBackup`، `verifyBackup`، `restorePreview`، `startRestore`، `getRecoveryEvidence`.
- **مدخلات:** sourceOwner، resourceScope، consistencyPoint، backupType، encryptionKeyRef، retentionPolicyRef، restoreTarget، approvalRef.
- **مخرجات:** backupId، manifestRef، checksumSet، consistencyStatus، verificationStatus، restoreJobRef، evidenceRef.
- **ضوابط:** تشفير أثناء النقل والتخزين؛ فصل صلاحية النسخ عن صلاحية فك التشفير والاستعادة؛ عدم اعتبار النسخة ناجحة قبل التحقق؛ حماية النسخ من الحذف غير المصرح؛ اختبار الاستعادة؛ وتسجيل كل استعادة.
- **قرارات مفتوحة:** topology، مفاتيح التشفير ومالكها، نطاقات النسخ، النسخ العابرة للمناطق، RPO/RTO الرقمية، مدد الاحتفاظ، وآلية الاستعادة المتسقة عبر أكثر من مالك.
- **أخطاء:** incomplete snapshot، checksum mismatch، key unavailable، retention conflict، restore authorization denied، dependency unavailable.
- **اختبارات:** BAK-01 checksum غير مطابق يفشل التحقق؛ BAK-02 لا تبدأ استعادة دون صلاحية وموافقة مطلوبة؛ BAK-03 تقرير الاستعادة يثبت النتيجة الفعلية؛ BAK-04 لا تعلن النسخة متسقة إذا لم يؤكدها جميع مالكي البيانات المطلوبين.

### SH-16 — Knowledge Service | خدمة المعرفة والوثائق

**المسؤولية:** توفير الوصول إلى المعرفة والوثائق والفهرسة الدلالية ومراجع المصادر، مع إبقاء ملكية محتوى المجال لدى C12 أو المركز المنتج.

- **الملكية المقترحة:** تملك روابط الفهرسة والمعالجة المعرفية ومراجع الاستشهاد وبيانات provenance التشغيلية؛ المستند الأصلي ومحتواه وتصنيفه وقرار الاحتفاظ به يظل لدى مالكه.
- **المستهلكون المرشحون:** C12، مساعد المشروع، الوكلاء المصرح لهم، ومراكز تحتاج استرجاعاً موثقاً.
- **عمليات مرشحة:** `registerKnowledgeSource`، `indexKnowledgeItem`، `retrieveKnowledge`، `getCitation`، `invalidateIndexEntry`، `rebuildKnowledgeIndex`.
- **مدخلات:** sourceRef، owner، scope، classification، ACL reference، contentVersion، language، provenance metadata.
- **مخرجات:** ranked references، citation refs، source version، freshness، permission-filtered snippets.
- **ضوابط:** احترام صلاحيات المصدر عند الفهرسة والاسترجاع؛ إعادة التحقق قبل إظهار المقتطف؛ ربط كل إجابة بمراجعها؛ إزالة/إبطال نتائج النسخ المحذوفة أو التي سحبت صلاحيتها؛ وعدم اعتبار embedding أو نتيجة الاسترجاع مصدراً للحقيقة.
- **قرارات مفتوحة:** الحدود بين Knowledge وSearch، محرك الفهرسة/المتجهات، التحديث والحذف، الاحتفاظ، دعم اللغات، provenance schema، وسياسة المصادر المتعارضة.
- **أخطاء:** source unavailable، ACL stale، citation missing، index stale، content version mismatch، unsupported language.
- **اختبارات:** KNO-01 مصدر محمي لا يظهر لمستخدم غير مخول؛ KNO-02 كل مقتطف يعيد source/version reference؛ KNO-03 سحب صلاحية المصدر يمنع عرضه حتى لو بقي مفهرساً؛ KNO-04 إجابة بلا مصدر موثق لا تعرض كإجابة مستندة إلى المعرفة.

## 4. مصفوفة الملكية والحدود بين الخدمات

| الخدمة | ما تملكه الخدمة المشتركة | ما لا تملكه |
|---|---|---|
| SH-09 | سجل الحدث والتسليم والاشتراك | حقيقة بيانات المجال |
| SH-10 | metadata الإصدارات ومجموعات التغيير | محتوى المورد الدلالي |
| SH-11 | سجلات الاستهلاك والتجميع والميزانيات وفق اعتماد لاحق | أسعار مزود غير موثقة أو قرارات مالية للمجال |
| SH-12 | تعريفات وقيم الإعدادات المشتركة وتاريخها | أسرار خام أو قواعد مجال غير مفوضة |
| SH-13 | تعريفات الموصلات والاتصالات ومراجع الأسرار | بيانات اعتماد خارجية خام أو ملكية حساب المزود |
| SH-14 | القياسات والتنبيهات التشغيلية | بيانات الأعمال الأصلية |
| SH-15 | كتالوج النسخ والاستعادة وأدلتها | ملكية بيانات المصدر |
| SH-16 | الفهرسة ومراجع المعرفة والاستشهاد | ملكية المستند الأصلي أو صلاحياته الأصلية |

## 5. قرارات لا تحسمها هذه الوثيقة

1. لا تضيف هذه الوثيقة خدمات SH-17 أو SH-18 أو SH-19 أو SH-20.
2. لا تحسم الفصل 157 ولا تستبدل نصه المفقود.
3. لا تعتمد broker أو قاعدة بيانات أو محرك متجهات أو مزود تخزين أو تقنية مراقبة.
4. لا تعتمد عملة أو أسعاراً أو عتبات ميزانية.
5. لا تعتمد قيم RTO/RPO أو مدد احتفاظ.
6. لا تعتبر أسماء الكيانات والجداول المذكورة في الملف 23 ملكية نهائية.
7. لا تعتبر الاختبارات المقترحة منفذة أو ناجحة.

## 6. شروط الإغلاق والاعتماد

لا تغلق فجوة أي خدمة قبل استكمال: مالك الخدمة والبيانات؛ قائمة المستهلكين؛ request/response schemas؛ واجهات API والأحداث؛ الصلاحيات؛ تصنيف البيانات؛ الأخطاء؛ timeout/retry/idempotency؛ retention؛ المراقبة؛ حالات الاختبار؛ ومصدر الاعتماد.

**الخطوة التالية:** مطابقة كل بطاقة أعلاه مع مصفوفة ملكية الفصل 134 والوظائف الفعلية للمراكز، ثم إنشاء سجل عقود API/events موحد بمعرفات ثابتة، مع إبقاء جميع البنود المقترحة بانتظار مراجعة المالك.

**بوابة البرمجة:** هذه الوثيقة توسعة للمواصفات فقط، ولا تمنح إذناً ببدء التنفيذ أو تعديل كود Android الحالي.
