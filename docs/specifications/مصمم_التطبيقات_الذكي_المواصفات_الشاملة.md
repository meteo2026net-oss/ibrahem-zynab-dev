# الجزء الأول: الرؤية والمنتج

## 1.1 الملخص التنفيذي

مصمم التطبيقات الذكي منصة متكاملة تحول فكرة المستخدم إلى تطبيق جاهز عبر خطوات منظمة قابلة للمراجعة والاعتماد. لا يعتمد النظام على توليد كود مباشر غير قابل للتحكم، بل على دورة حياة كاملة تشمل:

**الفكرة → التحليل → التصميم → الوظائف → البيانات → البناء → الاختبار → الإطلاق → المراقبة**

الهدف: تمكين المستخدم (غير المبرمج أو المبرمج) من بناء تطبيقات احترافية متعددة المنصات باستخدام مزيج من الذكاء الاصطناعي والتحرير المرئي واللغة الطبيعية، مع ضمان الجودة والأمان والقابلية للتوسع.

## 1.2 المشكلة

1. بناء التطبيقات التقليدية يتطلب فرق عمل متخصصة ووقت طويل وتكلفة عالية.
2. أدوات Low-Code / No-Code الحالية محدودة في التخصيص أو تنتج كوداً صعب الصيانة.
3. توليد الكود بالذكاء الاصطناعي وحده ينتج نتائج غير متسقة وغير قابلة للمراجعة الجادة.
4. غياب منصة عربية متكاملة تدعم دورة حياة التطبيق الكاملة من الفكرة إلى الإطلاق.

## 1.3 الفرصة

1. توحيد مسار بناء التطبيقات خلف واجهة واحدة ذكية ومتعددة المنصات.
2. دمج الذكاء الاصطناعي مع التحرير المرئي واللغة الطبيعية في نظام واحد قابل للمراجعة.
3. توفير بيئة عربية كاملة (واجهة + وثائق + دعم) تناسب السوق المحلي والإقليمي.

## 1.4 الرؤية

أن تصبح المنصة المرجع الأول لبناء التطبيقات الذكية متعددة المنصات في المنطقة العربية، بحيث يستطيع أي مستخدم تحويل فكرته إلى منتج حقيقي بجودة احترافية.

## 1.5 الأهداف الاستراتيجية

1. تغطية دورة حياة التطبيق الكاملة.
2. دعم 4 منصات: Android، iOS، الويب، سطح المكتب.
3. توفير 14 مركزاً وظيفياً و251 شاشة منظمة.
4. تمكين المستخدم من المراجعة والاعتماد في كل مرحلة.
5. ضمان الأمان والجودة وقابلية الصيانة من اليوم الأول.

## 1.6 المستخدمون المستهدفون

| الشخصية | الوصف | الاحتياج الرئيسي | مستوى التقنية |
|---------|-------|------------------|---------------|
| رائد الأعمال / صاحب الفكرة | لديه فكرة تطبيق ويريد تحويلها لمنتج | بناء سريع بدون برمجة عميقة | مبتدئ إلى متوسط |
| مصمم UI/UX | يريد تصميم تطبيقات متعددة المنصات | معاينة وتصميم مرن + تصدير | متوسط |
| مطور / مهندس برمجيات | يريد تسريع البناء مع التحكم الكامل | توليد كود نظيف + قابلية التعديل | متقدم |
| مؤسسة / فريق | يريد بناء أنظمة داخلية أو منتجات | صلاحيات، تعاون، أمان، حوكمة | متفاوت |

## 1.7 نطاق المنتج

### ما يشمله النطاق (In Scope)
- منصة ويب رئيسية لإدارة المشاريع والتطبيقات.
- مصمم واجهات متعدد المنصات (Android / iOS / Web / Desktop).
- محرر صفحات بالذكاء الاصطناعي + التحرير اليدوي.
- نظام وظائف العناصر (محرر مرئي + لغة طبيعية).
- إدارة البيانات والربط مع قواعد البيانات وAPIs.
- نظام وكلاء ذكيين (Agents) للمساعدة في التحليل والتصميم والبناء.
- إدارة المشاريع والصلاحيات والتعاون.
- توليد الكود والبناء والاختبار والإطلاق.
- دعم اللغة العربية كلغة أساسية للواجهة والوثائق.

### ما خارج النطاق حالياً (Out of Scope)
- تطبيقات الألعاب ثلاثية الأبعاد المعقدة.
- أنظمة الوقت الحقيقي فائقة الحساسية (مثل التداول عالي التردد).
- أجهزة IoT المخصصة جداً خارج نطاق التطبيقات القياسية.
- استبدال كامل للتطبيق Android الحالي قبل تقييمه واعتماده.

# الجزء الثاني: المعمارية العامة

## 2.1 المبادئ المعمارية

1. **فصل الاهتمامات**: طبقات واضحة (عرض، منطق أعمال، بيانات، تكامل).
2. **التقنية المستقلة (IR)**: تمثيل وسيط (Intermediate Representation) للتصميم والوظائف يسمح بالتوليد لمنصات متعددة.
3. **الاعتماد على العقود**: APIs داخلية واضحة ومُوثّقة.
4. **الأمان من التصميم**: صلاحيات دقيقة، سجلات تدقيق، فصل بيئات.
5. **القابلية للمراجعة**: كل مخرج ذكي قابل للعرض والاعتماد قبل الدمج.
6. **التوطين أولاً**: العربية وRTL كأساس وليس إضافة لاحقة.

## 2.2 الطبقات المعمارية (10 طبقات مقترحة)

1. طبقة الواجهة (UI Layer) — Angular / Web + تطبيقات أصلية
2. طبقة العرض التقديمي (Presentation)
3. طبقة منطق الأعمال (Business Logic)
4. طبقة الوكلاء الذكيين (Agents Orchestration)
5. طبقة التمثيل الوسيط (IR — Intermediate Representation)
6. طبقة توليد الكود (Code Generation)
7. طبقة البيانات والنماذج (Data & Models)
8. طبقة التكامل وAPIs (Integration)
9. طبقة الأمان والصلاحيات (Security & Auth)
10. طبقة البنية التحتية والمراقبة (Infrastructure & Observability)

## 2.3 المنصات المستهدفة

| المنصة | التقنية المقترحة للتوليد | ملاحظات |
|--------|--------------------------|---------|
| Android | Kotlin + Jetpack Compose | يوجد تطبيق حالي في المستودع يجب تقييمه |
| iOS | Swift + SwiftUI | توليد لاحق |
| Web | Angular (مستهدف في المواصفات) | المنصة الرئيسية للإدارة |
| Desktop | Electron أو ما يعادله | مرحلة لاحقة |

## 2.4 ملاحظة حول التطبيق الحالي

يوجد في المستودع تطبيق Android مبني بـ Kotlin + Jetpack Compose + Firebase/Firestore.  
**القاعدة**: لا يُحذف ولا يُستبدل لمجرد وجود المواصفات الجديدة. يجب تقييمه أولاً واتخاذ قرار رسمي بإعادة الاستخدام أو الفصل أو الدمج.

**شاشة قائمة المشاريع (C01-S01):**
- زر **[+ مشروع جديد]** → يفتح C01-S02
- حقل **بحث** → تصفية حسب الاسم/الحالة
- فلتر **الحالة** (نشط / مؤرشف / مسودة)
- فلتر **المرحلة** (0–11)
- بطاقة مشروع → النقر يفتح C01-S03
- قائمة سياقية (⋯) لكل مشروع: فتح، تعديل، أرشفة، حذف، نسخ

**شاشة إنشاء مشروع (C01-S02):**
- حقل **اسم المشروع** (إلزامي)
- حقل **وصف الفكرة** (نص طويل أو رفع ملف)
- اختيار **قالب** (فارغ / من قالب جاهز / استيراد مواصفات)
- اختيار **المنصات المستهدفة** (Android, iOS, Web, Desktop) — متعدد
- زر **[إنشاء]** → ينشئ المشروع وينتقل إلى لوحة التحكم
- زر **[إلغاء]** → يعود للقائمة

**شاشة لوحة تحكم المشروع (C01-S03):**
- مؤشر **المرحلة الحالية** مع شريط تقدم
- قائمة **بوابات الاعتماد** وحالتها
- قسم **آخر النشاطات**
- أزرار سريعة: [الذهاب للتحليل] [الذهاب للتصميم] [البناء] [الإعدادات]
- زر **[طلب اعتماد المرحلة]** عند اكتمال شروط المرحلة

# الجزء السادس: خطة العمل المرحلية (12 مرحلة + 7 بوابات)

## 6.1 المبدأ الحاكم
> **لا برمجة قبل اكتمال استعادة المواصفات واعتمادها (عبور G1).**

## 6.2 المراحل

### المرحلة 0 — التأسيس والحوكمة
- تنظيف هيكل المستودع.
- تعريف أدوار الفريق وسير العمل.
- إعداد بيئات التطوير الأساسية.
- **المخرج:** مستودع منظم + وثيقة حوكمة معتمدة.
- **البوابة:** G0

### المرحلة 1 — استعادة المواصفات
- استكمال واستقرار جميع ملفات `docs/specifications`.
- سد الفجوات المسجلة.
- مراجعة واعتماد المواصفات رسمياً.
- **المخرج:** مواصفات كاملة ومعتمدة (لم تعد DRAFT).
- **البوابة:** G1 ← **شرط بدء أي برمجة**

### المرحلة 2 — المعمارية الأساسية
- تصميم الطبقات العشر.
- اختيار التقنيات والمكدس.
- تصميم نماذج البيانات الأساسية.
- **المخرج:** وثيقة معمارية معتمدة + قرارات تقنية موثقة.
- **البوابة:** G2

### المرحلة 3 — الخدمات المشتركة
- طبقة الخدمات المشتركة (مصادقة، صلاحيات، ملفات، إشعارات...).

## مثال تفصيلي — المركز 04: مركز الوظائف

### السيناريو
ربط زر **«أضف للسلة»** بوظيفة حقيقية.

### التدفق — محرر مرئي

1. يحدد أحمد زر «أضف للسلة» في Canvas.
2. من لوحة الخصائص يضغط **[ربط وظيفة]**.
3. يفتح **محرر الإجراءات المرئي (C04-S02)**.
4. يختار الحدث: `عند النقر (onClick)`.
5. يضيف الخطوات بالترتيب:

| الترتيب | الإجراء | التفاصيل |
|---------|---------|----------|
| 1 | التحقق من تسجيل الدخول | إذا لم يكن مسجلاً → افتح شاشة تسجيل الدخول ثم عد |
| 2 | قراءة كمية افتراضية | quantity = 1 |
| 3 | استدعاء API / دالة | addToCart(productId, quantity) |
| 4 | عند النجاح | عرض رسالة «تمت الإضافة إلى السلة» + تحديث شارة السلة |
| 5 | عند الفشل | عرض رسالة الخطأ القادمة من الخادم |

6. يضغط **[عرض التسلسل]** لمراجعة المخطط.
7. يضغط **[اختبار]** ويجرب الحالة «مستخدم مسجل» و«غير مسجل».
8. يضغط **[حفظ الوظيفة]**.

### نفس الوظيفة باللغة الطبيعية (بديل)

في **محرر اللغة الطبيعية (C04-S03)** يكتب:
```
عندما يضغط المستخدم على زر أضف للسلة:
إذا لم يكن مسجلاً للدخول، افتح شاشة تسجيل الدخول.
بعد تسجيل الدخول أو إذا كان مسجلاً مسبقاً، أضف المنتج الحالي بكمية 1 إلى سلة المستخدم.
إذا نجحت العملية أظهر رسالة نجاح وحدّث عداد السلة.
إذا فشلت أظهر رسالة الخطأ.
```
ثم يضغط **[تحويل إلى منطق]** ويراجع النتيجة ويعتمدها.

## مثال تفصيلي — المركز 07: مركز البناء

## مثال تفصيلي — المركز 08: مركز الاختبار

### السيناريو
خطة اختبار لمسار «إضافة إلى السلة وإتمام الطلب».

### حالات اختبار (مثال)

| المعرف | الحالة | الخطوات | النتيجة المتوقعة |
|--------|--------|---------|------------------|
| TC-01 | إضافة للسلة — مستخدم مسجل | فتح منتج → أضف للسلة | رسالة نجاح + زيادة العداد |
| TC-02 | إضافة للسلة — غير مسجل | فتح منتج → أضف للسلة | الانتقال لتسجيل الدخول |
| TC-03 | إتمام طلب بسلة فارغة | فتح إتمام الطلب مباشرة | رسالة «السلة فارغة» ومنع المتابعة |
| TC-04 | إتمام طلب ناجح | سلة بها منتجات → إتمام → تأكيد | إنشاء طلب بحالة «جديد» وتفريغ السلة |
| TC-05 | عرض طلباتي | بعد إنشاء طلب → شاشة طلباتي | ظهور الطلب مع حالته |

### التنفيذ
- أحمد يشغّل **[تشغيل المحدد]** على TC-01 إلى TC-04.
- يسجّل النتيجة يدوياً أو آلياً إن وُجدت اختبارات آلية.
- يصدّر تقرير التغطية.

## مثال تفصيلي — المركز 11: مركز الأمان والصلاحيات
