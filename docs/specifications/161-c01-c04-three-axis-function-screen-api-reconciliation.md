# 161 — التسوية الثلاثية لوظائف وشاشات وعمليات API في C01–C04

**التاريخ:** 2026-11-16  
**الحالة:** DERIVED TRACEABILITY AUDIT / SEMANTIC CANDIDATES / OWNER REVIEW REQUIRED / NOT APPROVED  
**النطاق:** 57 وظيفة مصدرية، و58 شاشة مرشحة في الكتالوج 19، وعمليات API المقترحة للمراكز C01–C04 في سجل 97.  
**المصادر المباشرة:** Export 07، الأقسام B-01..B-04؛ سجل الوظائف 144؛ مطابقة الوظائف وعمليات API 145؛ تسوية كتالوج الشاشات 159؛ مطابقة الوظائف بالشاشات 160؛ سجل العمليات 97؛ وسجل الاختبارات/المعرفات المصدرية 141–143 و104.

## 1. لماذا أُنشئت هذه التسوية

الوثائق 145 و160 أعدت كل واحدة مطابقة ثنائية مستقلة: وظيفة→عملية API، ووظيفة→شاشة. هذه الوثيقة تجمع النتيجتين في مراجعة واحدة حتى لا يظهر أن وجود شاشة واسم عملية متقارب يثبت وحده عقداً كاملاً. كما تفصل الوظيفة المصدرية عن الشاشة وعن العملية وعن الاختبار، وتحافظ على اختلاف أنواع المعرفات.

لا تنشئ هذه الوثيقة معرفات مصدرية أو API جديدة، ولا تعتمد أسماء العمليات أو ملكيتها أو مخطط بياناتها. جميع العلاقات الموروثة من 145 و160 تبقى مرشحة دلالية فقط.

| Function ID | الوظيفة المصدرية | شاشة مرشحة من 160 | وضع API في 145 | مسار المراجعة المطلوب دون افتراض الملكية |

هذه حالات **NOT-MAPPED / REVIEW** وليست أوامر بإضافة أربع عمليات جديدة. قد تكون بعض القدرات داخلية أو مستهلكة لخدمة مشتركة، ولا يحدد هذا التدقيق Domain SoR أو API Owner.

## 4. مخاطر الازدواجية أو الاتساع الزائد في المطابقة الحالية

1. **تعدد الوظائف على عملية واحدة:** عدة وظائف C02 مثل تحرير الخصائص والنصوص والتخطيطات والتفاعلات ونظام التصميم ترتبط بـsaveDesignChangeSet. يلزم توضيح هل هذا عقد حفظ موحد بموارد/أنواع تغييرات واضحة أم أن العملية تخفي عدة عمليات مختلفة.
2. **تجميع وظائف التنقل:** عدة وظائف C03 تستخدم updateNavigationGraph. يجب تمييز تعديل الرسم من إدارة القوائم وأشرطة التنقل والانتقالات، وتحديد حدود كل مورد.
3. **نطاق C04 واسع:** defineConstraint مرشح لأنواع البيانات والقيود؛ يجب التحقق من تغطيته صراحة لأنواع الحقول والتحقق والقيود، لا افتراض ذلك من الاسم.
4. **الاعتماديات المشتركة:** حماية الصفحات وملفات التخزين واقتراحات AI قد تتطلب تكاملاً مع C10/C08/C06، لكن لا يجوز أن يؤدي ذلك إلى نقل ملكية بيانات المجال أو إنشاء نسخ مكررة من خدمات الصلاحيات والتخزين والوكلاء.
5. **القراءة والكتابة:** getDesignDocument غير مربوط بوظيفة، في حين لا ينبغي افتراض أن كل وظيفة شاشة تحتاج API مستقلاً؛ قد تكون قراءة الشاشة جزءاً من عقد استعلام مشترك.

## 5. C04-SCR-01 والشاشة الإضافية

يحتوي C04 على 16 وظيفة مصدرية و17 شاشة. تظل C04-SCR-01 «الرئيسية» شاشة ملخص/دخول غير مسندة إلى وظيفة واحدة. يجب على مالك المركز تحديد ما إذا كانت:
- لوحة ملخص تجمع قراءات من وظائف متعددة؛
- شاشة تنقل/دخول لا تملك وظيفة مجال مستقلة؛
- أو وظيفة مصدرية مستقلة لم يظهر لها معرف في B-04.

لا يُنشأ Function ID جديد ولا يُعاد تفسير الشاشة قبل هذا القرار.

## 6. ما الذي يلزم لإغلاق كل صف

يجب أن يحتوي سجل الإغلاق النهائي لكل وظيفة على:
1. Function ID وعنوان المصدر وموضعه الدقيق في Export 07.
2. شاشة أساسية/مساعدة أو أكثر من شاشة، مع سبب العلاقة واتجاه cardinality.
3. عملية API أو بيان موثق أن الوظيفة داخلية/تستهلك خدمة مشتركة/لا تحتاج API مستقلاً.
4. API Owner وDomain SoR وShared Service SoR عند انطباقهما، بقرار مالك لا باشتقاق آلي.
5. Permission، ونطاق المؤسسة/مساحة العمل/المشروع، وحقول الطلب والاستجابة، وحالات الفشل، وidempotency/versioning.
6. أحداث التدقيق والإشعارات وحدود producer/consumer.
7. معرف اختبار محدد يغطي أثر العملية وشروطها ونتيجتها المتوقعة، مع بيئة تشغيل ودليل ونتيجة فعلية.
8. حالة اعتماد مستقلة لكل من الوظيفة والشاشة وعقد API والاختبار.

## 7. ترتيب المعالجة المقترح

- **أولوية 1:** مراجعة الوظائف الأربع غير المربوطة بعملية، وتحديد حدود C03/C06/C08/C10 دون إنشاء API مسبقاً.
- **أولوية 2:** حسم OP-C02-019 وعلاقتها بوظائف C02.
- **أولوية 3:** مراجعة العمليات المشتركة بين عدة وظائف، خصوصاً saveDesignChangeSet وupdateNavigationGraph وdefineConstraint، وتثبيت حدود الموارد والعمليات.
- **أولوية 4:** اعتماد علاقة C04-SCR-01 بالوظائف أو توثيق كونها شاشة تجميعية.
- **أولوية 5:** إنشاء روابط اختبار مفردة بعد تحديد expected result وfixture والبيئة؛ لا تستخدم عائلة اختبار المركز كدليل تغطية لعملية مفردة.
- **أولوية 6:** تحديث سجل 97 وكتالوج الاختبارات فقط بعد اعتماد المالك، مع حفظ provenance وعدم الكتابة فوق معرفات المصدر.

## 8. الحكم

أصبحت المطابقة الثلاثية أوضح: 57 وظيفة مصدرية، 58 شاشة مشتقة، 53 وظيفة لها مرشح API، أربع وظائف بلا مرشح API واضح، وعملية واحدة C02 غير مربوطة بوظيفة. هذه نتيجة تدقيق قابلة للمراجعة، وليست اكتمالاً وظيفياً أو تعاقدياً.

لا توجد روابط exact/approved للوظائف بالشاشات أو بعمليات API، ولا روابط Operation→Test exact مثبتة، ولا اختبارات منفذة. لا تعيين مالك أو Domain SoR هنا، ولا إضافة APIs أو schemas أو جداول أو كود.

**لم يُعدّل كود التطبيق. البرمجة ما زالت غير مصرح بها حتى اكتمال المواصفات وموافقة المستخدم الصريحة المستقلة على بدء البرمجة.**
