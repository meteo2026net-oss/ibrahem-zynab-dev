# 81 — تدقيق اتساق معرفات الملكية وعقود API والاختبارات C01–C14

**التاريخ:** 2026-11-15  
**الحالة:** SOURCE-BASED CONSISTENCY AUDIT / CORRECTION REQUIRED / NOT APPROVED / NO IMPLEMENTATION  
**النطاق:** الوثائق 23، 25، 36، 72، 76–80، مع التحقق من فهارس المواصفات.  
**الغرض:** كشف التصادمات بين معرفات قرارات الملكية، والتحقق من أن عقود التفويض وواجهات API والأحداث والاختبارات لا تشير إلى سجلات قرار ملتبسة.

## 1. النتيجة التنفيذية

ظهر تصادم فعلي في namespace المعرفات: الوثيقة 36 والوثيقة 72 تستخدمان المعرفات نفسها `OWN-01..OWN-10` لكن بمعانٍ مختلفة وترتيب مختلف. الوثيقة 76 تتبنى معاني الوثيقة 72، بينما الوثيقة 36 تحتفظ بالمعاني الأقدم. لذلك فإن الإحالة المجردة إلى `OWN-01` أو `OWN-03` لا تحدد قرار الملكية المقصود دون ذكر الوثيقة.

**الأثر:** يمكن أن تشير إحالة في كتالوج الحقول أو اختبار قبول إلى موضوع خاطئ إذا لم تُذكر الوثيقة/المصدر. لا يجوز دمج السجلين أو إعادة ترقيمهما بصمت، ولا يجوز اعتبار أي من القرارات معتمداً؛ كل السجلات المعنية ما زالت مقترحات مفتوحة.

## 4. المعالجة الموصى بها

1. **الحفاظ على السجل التاريخي:** لا تُعدّل معاني OWN في الوثيقة 36 ولا تُحذف.
2. **تثبيت namespace فريد:** عند التحديث القادم، استخدم معرفات مؤهلة بالمصدر مثل `OWN36-01..OWN36-10` و`OWN72-01..OWN72-10`، أو معرفات قرار عالمية جديدة مع جدول aliases. لا تستخدم `OWN-xx` منفرداً في الوثائق الجديدة.
3. **إحالات صريحة:** كل إحالة في 73–80 يجب أن تذكر معرف القرار المؤهل والوثيقة المرجعية، لا الرقم المختصر وحده.
4. **استكمال النواقص:** أضف إلى حزمة القرار المستقبلية قراراً مستقلاً لـSH-11/التكلفة والميزانيات، وآخر للمؤسسة/مساحة العمل، وقراراً واضحاً لتعريفات الأدوار والأذونات؛ أو وثق دمجها وسببه بموافقة أصحابها.
5. **مراجعة المالكين:** تبقى كل البنود OPEN حتى موافقة أصحاب C01–C14 وSH-01–SH-16 بحسب الاختصاص. لا تنشئ هذه المراجعة موافقة نيابة عنهم.
6. **عدم تحديث baseline 36 قبل الاعتماد:** بعد صدور قرارات موثقة فقط، تُحدّث 36 بإضافة cross-reference وتاريخ القرار مع إبقاء سجلها التاريخي.

## 5. اتساق عقود التفويض وAPI والأحداث والاختبارات

### 5.1 التفويض — الوثيقة 78
- المصفوفة تربط العمليات بـactor/action/resource/scope، وتفرض التحقق الخادمي وإعادة فحص التفويض للمهام والأحداث المؤجلة.
- اختبارات AUTH-78-01..15 موصوفة فقط، وكلها NOT RUN.
- يجب أن تشير قرارات الملكية في المراجعات التالية إلى معرفات مؤهلة؛ لا يُعد التصادم دليلاً على خلل في التفويض المنفذ، إذ لا توجد صلاحيات منفذة بهذه الوثيقة.

### 5.2 API/Event/Approval — الوثيقة 79
- السجل يميز سياق الطلب المستعاد من الوثيقة 25 عن العمليات والأحداث وschemas المقترحة.
- الاختبارات API-79 وEVT-79 وAPR-79 موسومة SPECIFIED / NOT RUN.
- يلزم أن تتضمن سجلات API/Event/Approval مالك Domain SoR ومرجع قرار الملكية المؤهل، مع actor/action/resource/scope وcontractVersion وidempotency/concurrency وapproval hash عند انطباقها.
- لا توجد في هذه المراجعة أدلة على تنفيذ API أو event broker أو approval workflow.

### 5.3 اختبارات القبول — الوثيقة 80
- INT-80-01..18 تغطي SoR، الاتصال البيني، scope، الإصدارات، idempotency، concurrency، الموافقات، سحب التفويض، audit، search ACL، الأسرار، projections، AI governance، retention، recovery، migrations.
- SEC-80-01..16 تغطي حالات أمن وخصوصية سلبية.
- INT-80-16/17/18 تبقى BLOCKED بسبب سياسات الاحتفاظ/الحجز القانوني وRTO/RPO وملكية/سياسة الترحيل.
- يجب إضافة فحص آلي يمنع تكرار decision IDs عبر الوثائق أو يفرض namespace مؤهلاً. هذا الفحص مقترح ولم يُنفذ.
