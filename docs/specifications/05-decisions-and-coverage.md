## 2. قرارات تقنية مبدئية قيد المراجعة

ظهر خط أساس مبدئي لخدمات TypeScript/NestJS وPython، PostgreSQL، S3-compatible object storage، pgvector، Redis/Valkey، BullMQ، WebSocket/SSE، OpenTelemetry، GitHub Actions، OIDC/OAuth2 مع Keycloak كخيار، مدير أسرار وسجل تدقيق. هذه القائمة لا تُعامل كاعتماد نهائي لكل منتج أو إصدار؛ راجع [خط الأساس التقني](10-technical-baseline-and-open-choices.md).


### قرار أمني يحتاج حسم الحالة — SEC-REV-01 (Zero Trust)

| الحقل | القيمة |
|---|---|
| المصدر | الفصل 158.7 يذكر Zero Trust ضمن المتطلبات الإلزامية، بينما الفصل 158.9 يدرجه كقرار مقترح SEC-REV-01 |
| الحالة في سجل المشروع | PROPOSED / PENDING_USER — لا يوجد في الأرشيف المتاح إثبات موافقة مستقلة يحسم التعارض |
| الإجراء | إبقاء الضوابط المحددة الأخرى مثل أقل صلاحية والتحقق عند كل طلب وحماية الأسرار متطلبات مستقلة حيث اعتمدت؛ وعدم ترقية تسمية Zero Trust إلى APPROVED حتى توثيق الموافقة |
| أثر عدم الحسم | لا يصدر سجل قرارات نهائي متسق قبل تحديد الحالة أو تسجيل قرار صريح بعدم اعتمادها |

اختبارات SEC-FINAL-01..12 الواردة في الفصل 158 تظل معايير قبول مقترحة؛ لا تعني أن الاختبارات نُفذت أو اجتازت.


### مواءمة المحاور الوظيفية والمبادئ المستعادة من المصادر الإضافية

أكدت المصادر المكتبية الإضافية وجود قائمة مرجعية من 64 محوراً وظيفياً سبق اعتمادها. لا تُعد هذه المحاور مراكز مستقلة، ولا تحل محل المراكز الأربعة عشر أو الطبقات العشر. تفاصيل المواءمة والفجوات موثقة في [الملف 37 — مواءمة المصادر الإضافية والمحاور الوظيفية](37-supplemental-source-reconciliation-and-functional-crosswalk.md).

كما تؤكد المصادر مبادئ التصميم المرئي ومساعدة AI معاً، والتحرير المباشر من المعاينة، ونظام المكونات المختلط، والمعاينة المستقلة للمنصات، واستقلالية التنفيذ ضمن السياسات والموافقات. تُعد هذه المبادئ متسقة مع ADR-005 إلى ADR-009 وADR-012 إلى ADR-014؛ ولا تنشئ قرارات مكررة.

تظل المطابقة بنداً ببند للمحاور الـ64 مع المتطلبات والوظائف والشاشات والبيانات والعقود والصلاحيات والاختبارات فجوة مفتوحة (GAP-044). لا يُستنتج اكتمال التغطية من مجرد ذكر المحور أو المركز.

## 3. قرارات تحتاج مراجعة أو تفصيلاً

- التقنية النهائية لكل خدمة خلفية وقاعدة بيانات للمصمم نفسه.
- دور التطبيق Android/Kotlin الحالي وما يمكن إعادة استخدامه.
- خطة انتقال من المكونات الحالية إلى البنية المستهدفة إن لزم.
- اختيار محرك تدفقات قابل للتبديل وعقده.
- قائمة المحولات المدعومة في الإصدار الأول.
- مزود التخزين والنسخ الاحتياطي وموقع البيانات.
- سياسة الاحتفاظ والحذف والخصوصية حسب الأسواق المستهدفة.
- حدود التكلفة والميزانيات الافتراضية.
- أهداف RTO/RPO ومستويات الخدمة.
- تفاصيل الوظائف والاختبارات الأصلية لكل مركز.
- تفاصيل عقود APIs والأحداث.
- تفاصيل تنفيذ ADR-024 إلى ADR-028: سياسات العزل حسب نوع البيانات، عقود الإضافات، تفاصيل اختبار الحوكمة، وأهداف RTO/RPO الرقمية.

## 6. مصفوفة التتبع المطلوبة

يجب أن تتوفر سلسلة تتبع لكل متطلب:

`GOAL → BR → REQ → FUNC → SCR / DATA / API / PERM → TEST → EVIDENCE → RELEASE`

- GOAL: هدف المنتج.
- BR: هدف العمل.
- REQ: المتطلب.
- FUNC: الوظيفة.
- SCR: الشاشة.
- DATA: الكيان أو البيانات.
- API: العقد أو العملية.
- PERM: الصلاحية.
- TEST: الاختبار.
- EVIDENCE: دليل التنفيذ والنتيجة.
- RELEASE: الإصدار الذي يحتوي الوظيفة.

لا يُقبل متطلب حرج بلا اختبار ودليل نتيجة.

## 7. قواعد تحديث السجل

- لا يُحوّل PROPOSED إلى APPROVED دون قرار واضح.
- لا يُحذف قرار قديم؛ يوسم SUPERSEDED ويرتبط بالقرار البديل.
- لا يُعدّل متطلب معتمد بصمت؛ ينشأ Change Request وتحليل أثر.
- كل تغيير يحدد الملفات والبيانات والعقود والاختبارات المتأثرة.
- لا يُعتمد توثيق مختصر على أنه مواصفة تنفيذ كاملة.


## 8. ملاحظات تدقيق مستعادة من الفصول 125 و141 و158–163

- الفصل 125 يوفر تفاصيل مستعادة للشاشات 11–20 وكتالوج بيانات واسعاً، لكنه لا يغلق وحده مراجعة الشاشات 1–10 أو عقود كل موفر.
- الفصل 141 يحدد نموذجاً واسعاً لإدارة التكلفة، لكن العتبات الرقمية والميزانيات الهرمية ما زالت توصيات أو تفاصيل غير محسومة وليست اعتماداً مالياً نهائياً.
- الفصل 158 يحتوي تناقضاً داخلياً في تصنيف Zero Trust، كما أن وصفه لا يمثل اختبار اختراق فعلياً.
- الفصلان 158 و159 يعرضان C14 كالتشغيل والاستمرارية؛ المرجع المعتمد هو C14 لوحة التحكم الرئيسية، والتشغيل والاستمرارية قدرة مشتركة في L9/L10.
- الفصل 160 سابق زمنياً لقرارات ADR-024..028، لذلك يجب دمجها في سجل القرار النهائي دون طمس تاريخ الفصل.
- الفصلان 161–163 يضعان بوابة واضحة: اعتماد المواصفات لا يساوي إذن بدء البرمجة.
