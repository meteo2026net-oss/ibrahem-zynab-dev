# C13 — مركز الإعدادات

**مرجع النقاش:** الفصل 150  
**عدد الشاشات:** 20  
**اختبارات القبول المسجلة:** SET-001 إلى SET-084  
**الحالة:** قائمة الشاشات والهيكل العام مستعادان؛ يلزم استعادة النص الكامل لكل حالة اختبار ووصف تفصيلي لكل وظيفة قبل اعتماد التنفيذ.

## 1. الهدف والحدود

يدير المركز التفضيلات والقيم والسياسات والملفات التعريفية وإعدادات الخدمات على مستويات متعددة. لا يستبدل ملكية الأمن أو الذكاء الاصطناعي أو البناء والنشر أو الملفات أو النسخ الاحتياطي أو الاختبارات أو التكاملات؛ بل يضبط إعداداتها ضمن عقود وواجهات المراكز المالكة.

## 3. نموذج نطاق الإعدادات والتوريث

تدعم الإعدادات المستويات التالية:

`Platform → Organization → Workspace → Project → Environment → User → Session`

يجب تعريف:
- إعدادات قابلة للتوريث.
- إعدادات مفروضة لا يمكن تجاوزها من نطاق أدنى.
- إعدادات افتراضية.
- إعدادات شخصية لا تؤثر على بقية المستخدمين.
- أولوية حل التعارضات.
- إصدار لكل مجموعة إعدادات.
- سجل تغيير وسبب وتاريخ وفاعل.
- معاينة أثر التغيير قبل تطبيقه عند الحاجة.

## 5. المدخلات والمخرجات

**المدخلات:** النطاق المستهدف، مفتاح الإعداد، القيمة، نوع القيمة، مصدرها، سياسة التوريث، الدور، إصدار الإعداد الحالي، سبب التغيير، مرجع الموافقة عند الحاجة.

**المخرجات:** القيمة الفعالة، مصدر القيمة الفعالة، مستوى التوريث، التعارضات، الإصدار الجديد، نتيجة التحقق، سجل التغيير، وحالة الموافقة.

## 6. الصلاحيات

- المستخدم: تعديل تفضيلاته الشخصية المسموح بها.
- مالك المشروع: تعديل إعدادات المشروع ضمن حدود المؤسسة.
- مدير مساحة العمل: تعديل إعدادات مساحة العمل.
- مدير المؤسسة: إدارة السياسات المؤسسية.
- مسؤول المنصة: إدارة إعدادات المنصة العامة.
- مسؤول الأمن: مراجعة إعدادات الأمن والخصوصية.
- الوكيل: اقتراح تغيير أو إعداد مسودة فقط ما لم تمنحه سياسة صريحة صلاحية محددة؛ لا يوافق على تغييره بنفسه.
- المدقق: قراءة سجل التغييرات دون تعديله.

## 8. قواعد الأمن والتغيير

- لا تُخزن الأسرار في قيم الإعدادات كنص مكشوف؛ تحفظ مراجع إلى Secret Manager.
- لا يسمح إعداد أدنى بتجاوز سياسة أعلى مفروضة.
- لا يغير الوكيل صلاحياته أو سياسات الأمن.
- كل تغيير حساس يحتاج موافقة صالحة قبل التطبيق.
- إذا تغير نطاق العملية أو إصدارها تُراجع صلاحية الموافقة.
- لا يُنفذ تراجع قبل تحليل الآثار الجانبية والبيانات.
- لا تُصدّر الأسرار عند تصدير الإعدادات.
- يجب تسجيل القيم قبل وبعد التغيير بصورة آمنة ومقنّعة عند وجود أسرار.

## 9. الاختبارات

معرفات الاختبارات المستعادة: `SET-001` إلى `SET-084`. لا تتوفر حالياً تفاصيل نصية موثوقة لكل حالة اختبار على حدة في هذه الحزمة. يجب استعادة جدولها الأصلي وعدم اختراع توزيع غير موثق.

الحد الأدنى لاختبارات الاستكمال:
- صحة التوريث من Platform إلى Session.
- أولوية القيم المفروضة.
- منع تجاوز إعدادات المؤسسة من المشروع.
- عزل إعدادات مشروعين.
- عدم تسريب الأسرار في الواجهة أو السجلات أو التصدير.
- طلب موافقة للتغييرات الحساسة.
- رفض موافقة قديمة بعد تغير التغيير.
- حفظ سجل الإصدارات وإمكانية المقارنة.
- منع التراجع غير الآمن.
- كشف التعارضات والقيم غير الصالحة.

## 10. الاعتماديات

يعتمد المركز على الهوية والعضويات والصلاحيات والسياسات وسجل التدقيق. ويتكامل مع المراكز المالكة للتقنيات وAI والأتمتة والتكاملات والأمن والإشعارات والموارد والبناء والإصدارات. لا ينفذ إعدادات الخدمة نيابة عن المالك؛ بل يمررها عبر عقد موثق.
