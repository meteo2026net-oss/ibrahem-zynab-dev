# 52 — مسار استخراج المصدر الرئيسي من DOCX

**التاريخ:** 2026-11-15  
**الفرع:** main  
**الحالة:** EXTRACTION-TOOL-ADDED / LOCAL-SYNTHETIC-TEST-PASSED / REAL-SOURCE-RUN-PENDING

## 1. الهدف

تجهيز مسار قابل للتكرار لاستخراج النص والجداول من ملف المواصفات الرئيسي الموجود مسبقاً في المستودع، دون تعديل ملف المصدر أو بدء أي تنفيذ برمجي للمنتج.

المصدر المستهدف:
- `docs/specifications/00_MASTER_APPROVED_SPECIFICATIONS_SOURCE.docx`
- حجمه وبصمته مثبتان في التقرير 51.

## 2. الملفات التي أضيفت

| الملف | الغرض |
|---|---|
| `tools/specifications/extract_master_docx.py` | أداة Python تعتمد المكتبة القياسية فقط لقراءة حزمة DOCX واستخراج فقرات النص وخلايا الجداول |
| `.github/workflows/extract-master-specification.yml` | سير عمل GitHub Actions للتشغيل اليدوي أو عند تحديث الأداة/المصدر، ثم حفظ النص وملف بيانات البصمة كـ Artifact |

رابط سير العمل:
https://github.com/meteo2026net-oss/ibrahem-zynab-dev/actions/workflows/extract-master-specification.yml

## 3. حدود الاستخراج

الأداة:
- تقرأ `word/document.xml` وتستخرج النص بالترتيب البنيوي للفقرات والجداول.
- تشمل ملفات الرؤوس والتذييلات والحواشي السفلية والختامية إذا وجدت.
- تنتج ملف TXT وملف JSON يتضمن حجم المصدر وبصمة SHA-256 وحجم الناتج.
- لا تعدل DOCX الأصلي ولا تحتاج إلى أسرار أو صلاحية كتابة للمستودع.
- لا تعتمد على تثبيت حزم خارجية.

الاستخراج النصي لا يعيد إنتاج التخطيط المرئي أو الصور أو الرسوم البيانية أو المخططات المضمنة، ولا يغني عن مراجعة الصفحات المرئية عند وجود عناصر غير نصية. كما أن النص المستخرج ليس بديلاً عن ملف DOCX الأصلي.

## 4. التحقق المنفذ

تم تنفيذ تحقق محلي على نسخة اختبار DOCX مصطنعة:
- فحص صياغة Python باستخدام `py_compile`: ناجح.
- استخراج فقرة نصية وخلايا جدول من DOCX اختباري: ناجح.
- إنتاج ملف TXT وبيانات JSON ببصمة SHA-256: ناجح.
- بقاء المصدر الاختباري دون تعديل: متوافق مع تصميم الأداة.

هذا التحقق يثبت عمل الأداة على عينة بنيوية صغيرة فقط؛ ولا يثبت نجاح استخراج ملف المصدر الحقيقي ذي 6.8MB.

## 5. حالة تشغيل GitHub Actions

أضيف `workflow_dispatch` لتوفير تشغيل يدوي. لم يظهر تشغيل فعلي في استعلام GitHub Actions المتاح وقت إعداد هذا التقرير؛ لذلك لم يُنتج Artifact للمصدر الحقيقي بعد.

لا تُسجل الحالة على أنها «اكتمل استخراج المصدر». يلزم تشغيل سير العمل من صفحة Actions، ثم فحص Artifact الناتج والتحقق من:
1. بصمة المصدر المطابقة للتقرير 51.
2. اكتمال النص والجداول وعدم وجود أخطاء XML.
3. وجود جميع الأقسام المتوقعة وعدم وجود انقطاع أو اقتطاع.
4. مراجعة الصور والمخططات والصفحات ذات المحتوى المرئي بصورة منفصلة.

## 6. الأثر على المواصفات والبوابات

- لا يغير هذا العمل قرارات المنتج أو أسماء المراكز أو الطبقات.
- لا يغلق GAP-044.
- لا يعني اعتماد المواصفات أو عبور G1.
- لا يبدأ برمجة التطبيق ولا يعدل كود التطبيق الحالي.
- تظل الفروقات بين DOCX الكامل والملخص النصي والوثائق 00–51 مفتوحة إلى أن تتم قراءة المصدر الحقيقي ومطابقته بندياً.

## 7. الحالة النهائية

**المثبت:** أداة استخراج موجودة في المستودع، وسير عمل يدوي موجود، والاختبار المحلي الاصطناعي ناجح.

**غير المثبت بعد:** تشغيل سير العمل على DOCX الحقيقي، واستخراج النص الكامل، ومراجعة الصور/المخططات، وإنجاز المطابقة التفصيلية.

**الخطوة التالية:** تشغيل سير العمل اليدوي من GitHub Actions وفحص Artifact الناتج. لا حاجة إلى إعادة رفع DOCX؛ الملف موجود بالفعل في المستودع.
