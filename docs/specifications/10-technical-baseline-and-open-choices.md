## 2. خط أساس تقني مبدئي قيد المراجعة

ظهر في مراجعة الاعتماديات خط أساس مبدئي يتضمن:
- NestJS وTypeScript لخدمات التطبيق.
- Python للمعالجة والمهام المتخصصة.
- PostgreSQL للبيانات العلائقية.
- تخزين كائنات متوافق مع S3 للأصول.
- pgvector للبحث المتجهي عند الحاجة.
- Redis أو Valkey للتخزين المؤقت/التنسيق عند الحاجة.
- BullMQ للمهام الخلفية إذا اعتمدت بنية Redis المناسبة.
- WebSocket أو SSE للتحديثات الحية.
- OpenTelemetry للمراقبة والتتبع.
- GitHub Actions للفحوص وCI.
- OIDC/OAuth2، مع Keycloak كخيار يحتاج قراراً.
- مدير أسرار مركزي.
- سجل تدقيق مركزي.

**الحالة:** PRELIMINARY / PENDING TECHNICAL REVIEW. لا تعتبر هذه القائمة اعتماداً نهائياً لكل منتج أو مكتبة. يجب إجراء مقارنة بدائل، والتحقق من الترخيص والصيانة والتكلفة والأمن والتوافق مع متطلبات التشغيل قبل تثبيت الإصدارات.

## 3. خيارات التخزين

اقتُرح نمط تخزين هجين يجمع قواعد البيانات العلائقية وتخزين الكائنات وGit والبحث المتجهي والذاكرة المؤقتة وطوابير الأحداث وسجل التدقيق. الاقتراح لا يحدد وحده منتجات نهائية؛ يجب تحديد مالك كل نوع بيانات، سياسة الاحتفاظ، التشفير، النسخ الاحتياطي، الاستعادة، ومكان البيانات.

## 4. مزودو الذكاء الاصطناعي

المطلوب دعم طبقة مزودين/محولات حتى لا يرتبط المنتج بمزود واحد. ظهرت أسماء OpenAI وGemini وClaude وDeepSeek ضمن الخيارات التي ناقشها المشروع. لا يعني ذلك أن كل مزود مفعل أو متعاقد عليه أو متاح في كل بيئة.

يجب أن يدعم التصميم:
- إعداد بيانات اعتماد آمنة بمراجع إلى Secret Manager.
- اختيار المزود والنموذج وفق المهمة والسياسة.
- حدود تكلفة واستهلاك.
- مهلات وإعادة محاولة وبدائل.
- تسجيل النموذج والمزود والإصدار والتكلفة.
- عزل بيانات المشاريع.
- عدم إرسال محتوى حساس دون سياسة وموافقة مناسبة.

## 5. اللغات والمنصات المستهدفة

النطاق العام يشمل تطبيقات Android وiOS والويب وسطح المكتب، مع محولات للتقنيات واللغات. ناقش المشروع HTML/CSS/JavaScript/TypeScript، Python، Dart/Flutter، Kotlin، C#/.NET وSQL كعائلات تقنية مستهدفة أو محتملة. يجب تحديد قائمة دعم الإصدار الأول بشكل منفصل عن الرؤية طويلة الأمد.

## 6. تعارض المستودع الحالي

المستودع يحتوي حالياً تطبيق Android/Kotlin وJetpack Compose مع Firebase/Firestore. لا ينبغي افتراض أن وجود هذه الملفات يعني اعتماد Kotlin واجهةً للمصمم النهائي. Angular هو الاختيار المعتمد لواجهة المصمم المستهدف؛ ويجب تنفيذ تحليل فجوات لتحديد دور التطبيق الحالي وما يمكن إعادة استخدامه دون حذف أو نقل غير معتمد.
