# 28 — مصفوفة مواءمة طبقات الفصل 132 مع الطبقات الرسمية L1–L10

**الحالة:** DRAFT / ARCHITECTURE RECONCILIATION  
**المراجع:** قائمة الطبقات الرسمية في الملف 06، والفصل 132.3 و132.8–132.17 المستعاد في الملف 26.  
**الغرض:** منع وجود نموذجين متنافسين للمعمارية. هذه المصفوفة مواءمة تحليلية أولية وليست تغييراً لقائمة الطبقات المعتمدة.

## 1. القاعدة الحاكمة

قائمة L1–L10 هي الهيكل الرسمي المعتمد للمشروع. أما الطبقات العشر في الفصل 132 فهي تجميع منطقي ظهر في مصدر تاريخي، وبعضها يمثل واجهات اتصال أو قدرات مشتركة أو مجموعات خدمات، وليس طبقات مستقلة مطابقة واحداً لواحد.

لذلك:
- لا تستبدل L1–L10 بقائمة الفصل 132.
- لا تنشئ طبقات رسمية إضافية لمجرد أن الفصل 132 فصل بعض الوظائف.
- يمكن أن تمتد قدرة واحدة عبر أكثر من طبقة رسمية.
- يجب أن يكون لكل مكون موضع معماري أساسي واحد، مع توثيق واجهاته واعتمادياته العابرة للطبقات.

## 2. مرجع الطبقات الرسمية

| الرمز | الطبقة الرسمية | المسؤولية |
|---|---|---|
| L1 | واجهة المستخدم | shell، التنقل، شاشات المراكز، التفاعل المرئي |
| L2 | تجربة التصميم | محرر التصميم، التمثيل البصري، Design System والمعاينة |
| L3 | إدارة المشاريع | دورة المشروع، المتطلبات، التخطيط، التنسيق الوظيفي |
| L4 | محرك الذكاء الاصطناعي | Orchestrator، الوكلاء، النماذج، المهارات، الذاكرة والسياسات |
| L5 | محرك التنفيذ | محركات البرمجة والتوليد والتشغيل والبناء وسير الإجراءات |
| L6 | البيانات والتكاملات | نماذج البيانات، التخزين، APIs، الأحداث، الموصلات |
| L7 | الجودة والتحقق | تنفيذ الاختبارات والتحقق والتغطية وبوابات الجودة |
| L8 | الأمن والحوكمة | الهوية والتفويض والموافقات والسياسات والتدقيق والخصوصية |
| L9 | التشغيل والاستمرارية | المراقبة التشغيلية، الحوادث، النسخ الاحتياطي والتعافي |
| L10 | البنية التحتية | بيئات التشغيل والحوسبة والشبكات والتخزين والموارد الأساسية |

## 3. مواءمة طبقات الفصل 132

| طبقة الفصل 132 | المكونات المصدرية | الطبقة الرسمية الأساسية | امتدادات/اعتماديات | ملاحظات |
|---|---|---|---|---|
| تجربة المستخدم | Angular، shell، dashboard، workspaces، navigation | L1 | L2 وL3 | واجهة التصميم المتخصصة تدار في L2، وسياق المشروع في L3 |
| واجهات الاتصال | API Gateway، REST، WebSocket، validation، rate limiting، versioning | L6 | L1 وL3 وL8 وL9 | ليست طبقة رسمية مستقلة؛ بوابة اتصال وعقود مشتركة |
| الخدمات المشتركة | الهوية، الصلاحيات، الموافقات، التدقيق، الملفات، البحث، الإشعارات، المهام | موزعة حسب الملكية | L3 وL6 وL8 وL9 | كل خدمة توضع في طبقتها المالكة؛ لا تجمع كل الخدمات في طبقة واحدة |
| خدمات المراكز | قواعد المجال للمراكز الأربعة عشر | L3 بوصفها orchestration/project domain عند انطباقه | L2 وL5 وL6 وL7 وL8 | المراكز وحدات مجال؛ ليست كلها وظائف إدارة مشاريع |
| المحركات المتخصصة | Design، Rendering، Code Generation، Code Analysis، Workflow، Diagram، Test Execution، Build، Document Analysis | L5 | L2 وL4 وL7 | محرك التصميم ينسق مع L2، ومحرك الاختبار يخضع لبوابات L7 |
| تنسيق AI | Orchestrator، Agent/Model/Skill/Tool registries، Memory، Policy، Evaluation | L4 | L3 وL5 وL6 وL8 | L4 يخطط ويفوض؛ لا يملك صلاحيات تنفيذ مستقلة |
| البيانات والتخزين | relational، object، search/vector، cache، event store، backup | L6 | L9 وL10 وL8 | backup capability تشغيلي في L9، والتخزين الفيزيائي في L10 |
| التكاملات | GitHub، AI providers، external DB، hosting | L6 | L4 وL5 وL8 وL9 | إدارة الموصلات في L6؛ الأسرار والسياسات في L8 |
| الأمن والحوكمة | policies، audit، encryption، access monitoring | L8 | جميع الطبقات | ضوابط أفقية تفرض عبر واجهات كل طبقة |
| التشغيل والاستمرارية | health، failures، backups، recovery | L9 | L10 وL6 وL5 | التعافي يعتمد على بنية تحتية وخدمات بيانات سليمة |

## 4. فجوات التغطية بين النموذجين

1. **L2 تجربة التصميم:** الفصل 132 يذكر Design Engine وRendering Engine، لكنه لا يفصل تجربة التصميم باعتبارها طبقة رسمية مستقلة؛ يغطيها الفصل جزئياً فقط.
2. **L3 إدارة المشاريع:** الفصل 132 يصف خدمات المراكز، لكنه لا يفصل إدارة المشروع كطبقة مستقلة بحدودها ومصادر بياناتها.
3. **L7 الجودة والتحقق:** Test Execution Engine مذكور، لكن ملكية بوابات الجودة وتقرير الجودة وقرار الاعتماد تحتاج ربطاً صريحاً بـL7.
4. **L10 البنية التحتية:** الفصل 132 يذكر البيئات والموارد والتخزين، لكنه لا يقدم طبقة بنية تحتية مستقلة بعقودها ومؤشراتها.
5. **الخدمات المشتركة:** يلزم توزيع SH-01..SH-16 على الطبقات الرسمية حسب مسؤوليتها بدلاً من وضعها كلها في طبقة خدمات مشتركة غامضة.
6. **API Gateway:** يحتاج تعيين مالك تشغيلي واضح، مع فصل المصادقة والتفويض عن مجرد توجيه الطلبات.
7. **لوحة التحكم C14:** يجب أن تظل واجهة قراءة وتجميع في L1، وتستهلك مؤشرات من المراكز والخدمات المالكة؛ لا تصبح خدمة مجال مالكة للبيانات.

## 5. قواعد حسم ملكية المكونات

لكل مكون معماري يسجل:
- component_id واسم المكون وإصداره.
- الطبقة الرسمية الأساسية.
- المالك الوظيفي/المركز.
- المالك التشغيلي للخدمة عند اختلافه.
- واجهات الإدخال والإخراج.
- الخدمات التي يستهلكها ويقدمها.
- البيانات التي يملكها أو يقرأها.
- نطاقات التفويض المطلوبة.
- أحداثه وأحداثه المستهلكة.
- اختبارات الصحة والعقد والجودة والأمن.
- مؤشرات التشغيل والتكلفة.
- خطة التغيير والتوافق والتراجع.

## 6. اختبارات اتساق المعمارية

| المعرف المقترح | الاختبار | معيار النجاح |
|---|---|---|
| ARCH-XW-01 | تعيين كل مكون إلى طبقة رسمية | لا يوجد مكون بلا مالك طبقي |
| ARCH-XW-02 | مكون له أكثر من طبقة أساسية | يرفض التكرار أو يحدد primary layer واحدة |
| ARCH-XW-03 | خدمة مشتركة بلا مالك بيانات | لا تعتمد قبل تحديد مالك البيانات |
| ARCH-XW-04 | C14 يطلب بيانات مركز | يحصل على projection مصرح به من المالك، لا وصول مباشر |
| ARCH-XW-05 | محرك AI يطلب تنفيذ عملية | يمر عبر L5 وتفويض L8 والموافقة عند اشتراطها |
| ARCH-XW-06 | فشل بنية تحتية | تظهر مسؤولية L9/L10 ومسار التعافي |
| ARCH-XW-07 | اختبار جودة | يصدر القرار من L7 مع دليل مرتبط ببصمة الإصدار |
| ARCH-XW-08 | API Gateway | لا يحل محل التحقق من التفويض داخل الخدمة المالكة |

هذه اختبارات مقترحة للمراجعة وليست نتائج تنفيذ.

## 7. قرارات مطلوبة قبل اعتماد الخريطة

- اعتماد mapping رسمي لكل مكون وخدمة مشتركة.
- تعيين مالك لكل خدمة SH وطبقتها الأساسية.
- تحديد العلاقة بين C01 وL3 في إدارة المشروع والمتطلبات.
- تحديد موضع Workflow Engine بين L3 وL5 وSH-08 Task Service.
- تحديد موضع Document Analysis Engine بين L4 وL5 وC12.
- فصل خدمة Backup SH-15 عن البنية الفيزيائية L10 وعن عملية التعافي L9.
- تحديد حدود API Gateway وAuthorization Service وIdentity Service.

**الخلاصة:** الفصل 132 لا يناقض بالضرورة الطبقات الرسمية L1–L10، لكنه يستخدم تجميعاً مختلفاً. هذه المصفوفة توضح التداخلات وتحدد نقاط الحسم، وتبقي L1–L10 المرجع المعماري الرسمي.
