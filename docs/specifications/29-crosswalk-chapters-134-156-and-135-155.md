# 29 — مطابقة الفصول 134/156 و135/155 وسجل أدلة الاستعادة

**الحالة:** DRAFT / SOURCE RECONCILIATION  
**النطاق:** مقارنة المواد المتاحة في أرشيف المحادثات وملفات المواصفات 24 و25 و27 وسجل الفصول.  
**قاعدة الإثبات:** وجود فصل في الفهرس لا يثبت استعادة نصه؛ والأمثلة والعمليات المقترحة لا تعد APIs منشورة أو schemas معتمدة.

## 1. النتيجة التنفيذية

توجد مجموعتان من الفصول تتناولان موضوعات متقاربة:

- 134 و156: ملكية البيانات والمخطط الموحد.
- 135 و155: الاتصال بين المراكز وعقود APIs وحوكمتها.

المادة المتاحة تثبت أن الفصل 134 مستعاد بتفصيل منطقي، وأن الفصل 135 مستعاد بمصفوفة تفاعل وعمليات مقترحة ومعايير اختبار. كما استعيدت أجزاء تفصيلية من الفصل 155 تخص حوكمة العقود. أما الفصل 156 فلم يظهر له متن مستقل في ملفات المصدر التي أمكن فحصها في هذه الجولة؛ و157 ما زال مذكوراً كفصل مطلوب دون متن تفصيلي.

لا تدمج الفصول أو تحذف أرقامها التاريخية. تعتمد هذه الوثيقة خريطة علاقة مؤقتة تحفظ المصدر وتحدد ما يمكن استخلاصه وما يحتاج دليلاً إضافياً.

## 2. مصفوفة حالة الاستعادة

| الفصل | الموضوع | ما ثبت توفره | ما لا يثبت بعد |
|---|---|---|---|
| 134 | توحيد نموذج البيانات وملكية الجداول | تفاصيل 134.1–134.24 كما سجلها الفصل 11؛ مجموعات كيانات، ملكية المراكز، نماذج مشتركة، قواعد بيانات واختبارات DATA-01..18 | ERD نهائي، قاموس حقول مكتمل، اعتماد كل مالك ومصدر حقيقة واحتفاظ |

| 157 | توحيد المكونات والخدمات المشتركة | يظهر في سجل الفصول بعنوانه وحالة «مطلوب» | متن تفصيلي، قائمة خدمات نهائية، تغييرات SH، مالكون وعقود واختبارات |

## 3. مطابقة 134 مع 156 — البيانات

### 3.1 ما يغطيه الفصل 134 فعلياً

المادة المستعادة في الملف 24 تقسم البيانات منطقياً إلى مجموعات، وتغطي على الأقل:

- المؤسسات ومساحات العمل والمشاريع والعضويات.
- ملكية بيانات المراكز الأربعة عشر وحدود القراءة والكتابة.
- تتبع المتطلبات وإصدارات الموارد ولقطات المشروع.
- الموافقات والمهام ومحاولات التنفيذ والأحداث.
- الملفات والأصول وإصداراتها وروابطها وصلاحياتها.
- وكلاء AI ومهاراتهم وأدواتهم وسياقات الذاكرة ومزودي النماذج.
- الإعدادات متعددة النطاقات والهوية والتفويض وسجلات التدقيق.
- قواعد العزل والاحتفاظ والترحيل وسلامة العلاقات.
- معايير قبول DATA-01..18.

### 3.2 ما لا يجوز نسبته إلى الفصل 156 حالياً

لا تتوفر أدلة كافية لتحديد ما إذا كان الفصل 156:
1. إعادة صياغة للفصل 134؛ أو
2. توسيعاً له بمخطط موحد وحقول تفصيلية؛ أو
3. مراجعة لاحقة تغير ملكية بعض الجداول أو العلاقات؛ أو
4. فصلاً تجميعياً يجمع بيانات المراكز والخدمات المشتركة.

لذلك لا تنسب أي حقول أو جداول أو قرارات إضافية إلى 156 قبل العثور على نصه أو مرجع اعتماد موثوق.

### 3.3 مسار الدمج المستقبلي

عند استعادة 156، أنشئ جدول مقارنة لكل كيان يتضمن: معرف الكيان، الاسم في 134، الاسم في 156، المالك، مصدر الحقيقة، الحقول، العلاقات، مستوى العزل، التصنيف، الاحتفاظ، المستهلكون، التغيير، مصدر الدليل، وحالة القرار.

لا يعتمد ERD موحد قبل حل التعارضات وتحديد المالك ومصدر الحقيقة لكل كيان.

## 4. مطابقة 135 مع 155 — العقود البينية

### 4.1 توزيع المسؤولية بين الفصلين

| البعد | الفصل 135 | الفصل 155 |
|---|---|---|
| خريطة الاتصال | مصفوفة الطالب والمستقبل والعملية | سجل المستهلكين ومقدمي الخدمة ضمن حوكمة العقد |
| عمليات المجال | أمثلة عمليات لكل مركز | بطاقة عقد موحدة لكل عملية |
| شكل الرسائل | سياق طلب موحد وأنواع العقود | request_schema وresponse_schema |
| الأمن | التحقق من السياق والصلاحيات لدى الخدمة المستقبلة | authentication وauthorization وتصنيف البيانات |
| الأخطاء | معايير API-01..10 | نموذج أخطاء موحد |
| التكرار والتعافي | معايير أولية للطلب المكرر والمهلة والفشل | idempotency وretry وtimeout وcircuit breaker وغيرها |
| الإصدارات | توافق وتغييرات غير متوافقة | دورة حياة Draft إلى Retired وسياسة deprecation |
| الاختبار | API-01..10 | CONTRACT-01..12 |
| البيانات الإدارية | مالك ومستهلكون مطلوبان لكل علاقة | جداول حوكمة مقترحة للعقود والإصدارات والاختبارات |

### 4.2 قاعدة الكتالوج الموحد

يُنشأ لاحقاً سجل عقد واحد لكل عملية فعلية، ويحتوي على الأقل:

- contract_id ثابت واسم واضح.
- provider/owner center وservice owner.
- consumer centers مع تحديد الاستخدام.
- contract version وlifecycle status.
- HTTP method/path أو event/topic الفعلي.
- request/response schema وإصداراتها.
- authentication وauthorization وpermission scopes.
- data classification وtenant/project boundary.
- timeout وretry وrate limit وidempotency عند انطباقها.
- error codes وcorrelation/trace identifiers.
- compatibility وdeprecation policy.
- contract tests والبيئة ونتائج التنفيذ والأدلة.
- الموافقات وسجل التغيير.

### 4.3 منع الالتباس بين معرفات الاختبار والقرارات

المعرفات التالية تنتمي إلى نطاقات مختلفة ولا يجوز دمجها لمجرد تشابه الاسم:

- API-01..API-10: معايير اختبار الفصل 135.
- CONTRACT-01..CONTRACT-12: معايير اختبار الفصل 155.
- CONTRACT-ARCH-01..CONTRACT-ARCH-10: قرارات/مقترحات معمارية في الفصل 155.

يجب الاحتفاظ بالبادئة والنطاق المصدر عند بناء سجل التتبع، وإضافة معرف داخلي موحد فقط إذا اعتمد نظام التتبع ذلك صراحةً.

### 4.4 مثال ربط دون ادعاء التنفيذ

المثال المصدري POST /api/v1/design-analysis/jobs يصلح كعينة توضيحية في حوكمة العقد، لكنه لا يثبت أن endpoint موجود أو أن مخطط الطلب والاستجابة قد اعتمد. لا ينشأ عقد تنفيذي منه قبل تحديد المالك والمستهلك والصلاحيات والـschemas والاختبارات.

## 5. الفجوات المرتبطة

- GAP-013: الفصل 157 وقائمة الخدمات المشتركة.
- GAP-020: اكتمال عقود الاتصال وواجهات APIs.
- GAP-021: ERD وملكية البيانات وقاموس الحقول.
- GAP-031: مواءمة المكونات والخدمات مع الطبقات الرسمية.
- GAP-032: استعادة الفصل 156 ومقارنته بالفصل 134، والتحقق من أي فصول أو ملاحق إضافية تتعلق بتوحيد البيانات.

## 6. شروط الإغلاق

لا تغلق فجوات هذه المجموعة إلا بعد توفر الأدلة التالية:

1. متن الفصل 156 أو تأكيد موثق بأنه غير موجود في التصدير الكامل مع سجل مصدر واضح.
2. مقارنة بندية 134/156 تحدد الإضافات والتعارضات والنسخة المرجعية.
3. كتالوج كيانات مع مالك ومصدر حقيقة وحقول وعلاقات وتصنيف واحتفاظ وعزل.
4. مقارنة كل تفاعل في 135 بعقد 155 وبـschema ومستهلك وصلاحيات.
5. اختبارات عقد وبيانات قابلة للتنفيذ مع بيئة ونتيجة ودليل.
6. اعتماد المالك المعماري وأصحاب المراكز للنسخة الموحدة.

## 7. حدود العمل في هذه الجولة

- فُحصت أجزاء الأرشيف المتاحة 2026-11-09-export-part-01 إلى part-03 و2026-11-10-export-part-04 إلى part-07.
- ظهر الفصل 157 في سجل الفصول داخل part-03 وpart-06، ولم يظهر متن تفصيلي له في الأجزاء السبعة المفحوصة.
- لم يظهر متن مستقل للفصل 156 في الأجزاء السبعة المفحوصة؛ وهذا لا يثبت عدم وجوده في تصدير آخر أو رابط مشاركة غير متاح.
- لم تُنشأ قاعدة بيانات أو API أو schema تنفيذية.
- لم تُعدل ملفات التطبيق أو يبدأ تنفيذ برمجي.

**الخلاصة:** 134/135 و155 مواد قابلة للمقارنة والتكامل، لكن لا يوجد دليل كافٍ لاعتبار 156 مستعاداً أو لاعتبار عقود 135/155 مكتملة. تبقى هذه الوثيقة أداة مطابقة وتوجيه عمل، وليست اعتماداً نهائياً.
