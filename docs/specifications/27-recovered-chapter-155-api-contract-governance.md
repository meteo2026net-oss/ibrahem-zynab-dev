# 27 — استعادة الفصل 155: حوكمة عقود APIs والخدمات

**الحالة:** RECOVERED_DETAILED / PENDING RECONCILIATION  
**المصدر:** ملف التصدير 2026-11-09-export-part-03-of-03.txt، الفصل 155.  
**العلاقة:** يكمل الفصل 135 والملف 25؛ الفصل 135 يصف نموذج التواصل بين المراكز، بينما يضيف الفصل 155 حقول تعريف العقد ودورة حياته وأخطاءه وإعادة المحاولة وبيانات إدارته واختباراته.  
**تنبيه:** الأمثلة والعمليات الواردة في المصدر توضيحية/مقترحة، وليست APIs منشورة.

## 1. أهداف حوكمة العقود

- تعريف مالك لكل عقد ومستهلكيه.
- منع الاتصال المباشر غير المنضبط بقواعد بيانات مركز آخر.
- توحيد المصادقة والتفويض والأخطاء والمهل وإعادة المحاولة.
- تتبع توافق الإصدارات والمستهلكين المتأثرين.
- اختبار العقود قبل اعتمادها وتفعيلها.
- إدارة الإيقاف والتقاعد دون كسر المستهلكين.

## 3. نموذج موحد للأخطاء — الفصل 155.6

شكل الخطأ المقترح يتضمن error.code وerror.message وerror.correlation_id وerror.retryable.

| الفئة | المثال | التصرف |
|---|---|---|
| Validation | بيانات غير صالحة | إعادة الطلب بعد التصحيح |
| Authentication | هوية غير صحيحة | إعادة المصادقة |
| Authorization | صلاحية غير كافية | رفض الطلب |
| Not Found | المورد غير موجود | إظهار النتيجة المناسبة |
| Conflict | تعارض إصدار | طلب المراجعة |
| Rate Limit | تجاوز الحد | الانتظار وفق السياسة |
| Timeout | انتهاء المهلة | تقييم إمكانية الإعادة |
| Dependency Failure | تعطل خدمة تابعة | تطبيق سياسة الاستمرارية |
| Internal Error | خطأ داخلي | تسجيله ومعالجته |

لا تعرض stack traces أو الأسرار للمستخدم النهائي.

## 4. Idempotency وإعادة المحاولة — الفصل 155.7

العمليات المذكورة التي تحتاج مفاتيح منع التكرار عند ملاءمتها: إنشاء مشروع، طلب بناء، تشغيل اختبار، طلب تحليل AI، تنفيذ ترحيل، إرسال إشعار، طلب حذف، وتسجيل موافقة.

القواعد:
- لا تعاد العمليات غير الآمنة تلقائياً.
- تحديد عدد المحاولات والتدرج الزمني.
- تجنب إعادة إرسال طلب نُفذ بالفعل.
- استخدام correlation IDs.
- معالجة حالة النتيجة غير المعروفة بعد انقطاع الاتصال.

## 5. المرونة والمهل — الفصل 155.8

المفاهيم المطلوبة: Timeout، Retry، Circuit Breaker، Bulkhead Isolation، Rate Limiting، Dead Letter Queue، Health Checks.

لا تفرض مهلة واحدة على كل المراكز؛ يحدد كل مركز القيم المناسبة لطبيعة عملياته بعد مراجعة الأداء والاعتماديات.

## 6. دورة حياة العقد — الفصل 155.9

الحالات:
- Draft
- Under Review
- Approved
- Active
- Deprecated
- Retired

قواعد التوافق:
- إضافة حقل اختياري عادة أقل تأثيراً من تغيير نوع حقل قائم.
- حذف حقل أو تغيير معناه تغيير غير متوافق محتمل.
- تغيير المصادقة أو الصلاحيات عالي الأثر.
- سجل المستهلكين المتأثرين إلزامي.
- لا يزال العقد مستخدماً قبل معالجة المستهلكين أو اعتماد خطة انتقال.

اختبارات العقد تشمل مطابقة الطلب والاستجابة للمخطط، صلاحيات المستهلك، أخطاء الخدمة، حدود الاستخدام، التوافق الخلفي، التكرار وإعادة المحاولة، والتعطل والاستعادة.

## 10. العلاقة بالفصول 132 و134 و135

- الفصل 132 يضع المعمارية العامة والطبقات والخدمات المشتركة والأحداث والمهام.
- الفصل 134 يحدد ملكية الكيانات ومصدر الحقيقة والروابط بين المراكز.
- الفصل 135 يحدد أنواع العقود ومصفوفة التفاعل وعمليات أمثلة لمراكز المجال.
- الفصل 155 يحدد بطاقة تعريف العقد ودورة حياته وأخطاءه ومرونته وبيانات إدارته واختباراته.

يجب دمج هذه المواد في كتالوج واحد للعقود دون تكرار كيانات أو إصدارات أو معرفات.

## 11. الفجوات المتبقية

1. مطابقة كل عقد في الفصل 135 مع بطاقة الحقول الكاملة في الفصل 155.
2. تعريف schemas فعلية لكل عملية.
3. بناء قائمة شاملة بمستهلكي كل عقد.
4. تحديد owners ومصفوفة التفويض وبيانات التصنيف.
5. اعتماد timeout/retry/rate-limit حسب نوع العملية.
6. ربط contract tests ببيئات وأدلة تشغيل.
7. حسم أسماء الجداول النهائية مع مخطط البيانات.
8. دمج سياسات العقود مع نظام الإضافات والموصلات.
9. مطابقة معرفات CONTRACT-01..12 مع معرفات CONTRACT-ARCH-01..10 منعاً للالتباس.

**الخلاصة:** الفصل 155 يرفع مواصفات العقود من مصفوفة اتصال عامة إلى نموذج حوكمة قابل للتطبيق لاحقاً. لكنه لا يغلق GAP-020 قبل إكمال schemas والمستهلكين والصلاحيات والاختبارات والأدلة.
