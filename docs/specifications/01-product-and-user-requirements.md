# 01 — شرح البرنامج والرؤية والمتطلبات العامة

## 1. تعريف المنتج

مصمم التطبيقات الذكي منصة هندسة برمجيات بمساعدة الذكاء الاصطناعي. تستقبل فكرة أو متطلبات أو تصميماً أو ملفات مرجعية، وتحوّلها عبر خطوات يمكن مراجعتها واعتمادها إلى تطبيق منظم، قابل للتطوير والاختبار والنشر والصيانة.

المنصة ليست مولّد واجهات فقط، ولا تسمح للذكاء الاصطناعي بتنفيذ كل شيء بلا حدود. هي بيئة عمل فيها محركات وأدوات ووكلاء، مع سياسات وصلاحيات وموافقات وسجل تدقيق.

## 2. النتائج التي يجب أن يحققها المنتج

1. تحويل وصف المستخدم إلى متطلبات قابلة للاختبار.
2. اكتشاف النواقص والتعارضات والافتراضات قبل البناء.
3. تصميم الواجهات وتجربة الاستخدام بصرياً وبمساعدة AI.
4. إدارة الصفحات والمسارات والتنقل.
5. تصميم البيانات وقواعد البيانات والتخزين والمزامنة.
6. توليد الكود وتعديله وربطه بالمتطلبات والتصميم.
7. توزيع الأعمال على وكلاء متخصصين وتنسيقها.
8. اختبار الوظائف والجودة والأمن والأداء والتوافق.
9. إدارة الصور والملفات والوسائط والتراخيص.
10. ربط الخدمات الخارجية ومزودي AI والمستودعات.
11. تطبيق الحوكمة والصلاحيات والموافقات والتدقيق.
12. بناء التطبيق وإصداره ونشره ومراقبته.
13. حفظ المعرفة والقرارات والتوثيق والإصدارات.
14. الحفاظ على استمرارية المصمم نفسه والتعافي من الأعطال.

## 3. المستخدمون والأدوار

الأدوار النهائية يجب أن تكون قابلة للتخصيص وفق المشروع والمؤسسة، وتشمل على الأقل:
- مالك المشروع.
- مدير المؤسسة أو مساحة العمل.
- مدير المشروع.
- مصمم UI/UX.
- مهندس برمجيات.
- مهندس بيانات.
- مهندس جودة واختبار.
- مسؤول أمن.
- مسؤول إصدار ونشر.
- مراجع أو معتمد.
- مشاهد للقراءة فقط.
- وكيل ذكاء اصطناعي يعمل بصلاحيات محددة ومقيدة.

لا يُمنح الوكيل صلاحيات بشرية مطلقة، ولا يرفع صلاحياته بنفسه.

## 4. رحلة المستخدم الأساسية

1. إنشاء مشروع جديد.
2. كتابة فكرة المشروع وإرفاق المراجع والملفات.
3. تحليل المجال والمستخدمين والأهداف.
4. الإجابة عن أسئلة توضيحية تدريجية؛ سؤال واحد في كل مرة عندما يلزم.
5. استخراج المتطلبات الوظيفية وغير الوظيفية.
6. اكتشاف التعارضات والافتراضات والنواقص.
7. اقتراح المنصات والتقنيات مع شرح الأسباب والتكاليف والقيود.
8. إنشاء وثيقة متطلبات أولية.
9. مراجعة المستخدم واعتماد المتطلبات.
10. تصميم الصفحات والتدفقات والمكونات.
11. مراجعة التصميم واعتماده.
12. تصميم البيانات والتكاملات.
13. توليد خطة التنفيذ وتقسيمها إلى مهام.
14. تنفيذ المهام عبر المحركات والوكلاء ضمن الصلاحيات.
15. اختبار كل وحدة وربطها بمتطلباتها.
16. مراجعة الأمن والجودة.
17. إنشاء حزمة البناء.
18. موافقة مستقلة على النشر.
19. النشر التدريجي والمراقبة.
20. التوثيق والتسليم والصيانة.

## 6. المتطلبات غير الوظيفية

- **الأمان:** أقل صلاحية، عزل المؤسسات والمشاريع، إدارة أسرار آمنة، تحقق خادمي.
- **الخصوصية:** تقليل البيانات، تحديد أغراض المعالجة، الاحتفاظ والحذف وفق سياسة معتمدة.
- **الاعتمادية:** مهام قابلة للاستئناف، نقاط تحقق، منع تكرار العمليات الحساسة.
- **القابلية للتوسع:** محركات ومحولات وإضافات قابلة للتوسع دون ربط النظام بإطار واحد.
- **الأداء:** قياس P50/P90/P95/P99، ومراقبة زمن الاستجابة واستهلاك الموارد.
- **قابلية الصيانة:** وحدات واضحة، عقود موثقة، اختبارات آلية، سجل قرارات.
- **قابلية الوصول:** استهداف WCAG 2.2 AA عند ملاءمة الواجهة والمنصة.
- **التوافق:** معاينة واختبار مستقل لكل منصة وحجم شاشة.
- **قابلية المراقبة:** سجلات وأحداث ومقاييس وتنبيهات مرتبطة بمعرفات المهام والمشاريع.
- **الاستعادة:** نسخ احتياطية واختبار استعادة حقيقي، لا مجرد نجاح إنشاء النسخة.
- **قابلية التدقيق:** ربط كل تغيير بمنفذه وسببه وموافقته ونتيجة اختباره.
- **إدارة التكلفة:** ميزانيات وحدود وتنبيه قبل تجاوزها وعدم تشغيل مزود مدفوع بلا سياسة.

## 7. استقلالية المصمم

النمط المعتمد هو «مهندس مستقل تحت إشراف المستخدم»:
- ينفذ الأعمال الروتينية داخل النطاق والسياسات والميزانية.
- يشرح القرارات التقنية المهمة وأسبابها.
- يطلب الموافقة قبل القرارات عالية الأثر.
- لا يغيّر متطلبات أو مسارات معتمدة دون موافقة.
- لا ينشر أو يحذف بيانات إنتاجية أو يدوّر أسراراً أو يغيّر صلاحيات حرجة دون بوابة موافقة.
- يوقف التنفيذ عند وجود تعارض أو نقص مؤثر.

## 8. حالات المشروع

الحالات المعروفة:
`Draft`, `Analyzing`, `Needs Clarification`, `Review`, `Ready for Approval`, `Approved`, `Design Phase`, `On Hold`, `Archived`.

يجب توثيق انتقالات الحالات وشروط كل انتقال وصلاحياته قبل التنفيذ.

## 9. معيار نجاح المنتج

يُعد المنتج ناجحاً عندما يستطيع المستخدم الانتقال من فكرة موثقة إلى تطبيق مبني ومختبر ومراجع أمنياً وقابل للتسليم، مع سلسلة تتبع كاملة من المتطلب إلى الشاشة والبيانات والـAPI والاختبار والإصدار، ودون تنفيذ تغييرات عالية الأثر خارج الموافقات.
