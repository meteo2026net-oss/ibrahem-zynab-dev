## 3. التقنية الظاهرة في التطبيق القائم

من الملفات التي تمت قراءتها:
- Android مع Kotlin.
- واجهة Jetpack Compose وMaterial 3.
- Gradle Kotlin DSL.
- Firebase Authentication.
- Cloud Firestore.
- طبقات Repository للبيانات والتكاملات ومزودي الذكاء الاصطناعي والمهام المستمرة.
- عميل AI يتضمن موصلات لمزودين مثل Gemini وOpenAI وDeepSeek.
- نمط تنفيذ مهام متتابعة مع نقاط تحقق، وإيقاف مؤقت، وموافقة بشرية، وإعادة محاولة، ومفتاح idempotency.
- توجد اختبارات في `app/src/test` و`app/src/androidTest`.

هذه ملاحظات عن الملفات الموجودة، وليست حكماً بأن كل هذه الوظائف مكتملة أو آمنة أو مجتازة للاختبارات.

## 5. ملاحظة مهمة: تطبيق قائم مقابل المنتج المستهدف

هناك مستويان يجب فصلهما:

### أ. التطبيق الموجود في المستودع
تطبيق Android/Kotlin قائم، مع Firebase وواجهات Compose وطبقات بيانات وخدمات.

### ب. المنتج المستهدف وفق القرارات اللاحقة
منصة «مصمم التطبيقات الذكي» متعددة المنصات، تعتمد Angular واجهةً أساسية للمصمم، مع محرك تصميم ومحرك برمجة مستقلين عن إطار الواجهة، ومحولات تسمح بدعم تقنيات وتطبيقات متعددة.

**القرار الآمن:** لا تُحوّل التطبيق الحالي تلقائياً إلى Angular ولا تحذف أجزاءه. يجب إعداد تقييم فجوات وخطة انتقال معتمدة تحدد ما يُعاد استخدامه وما يُفصل وما يُستبدل وما يُبقى كتطبيق مساعد أو واجهة إدارية.

## 6. عناصر تستوجب مراجعة تقنية قبل الإنتاج

- مراجعة قواعد Firestore والتحقق من عزل المستخدمين والمشاريع على الخادم.
- التحقق من أن مفاتيح المزودين والأسرار لا تُحفظ كنص صريح ولا تُرسل إلى الواجهة أو السجلات.
- مراجعة حماية مفاتيح API ودورة تدويرها وانتهاء صلاحيتها.
- اختبار صلاحيات الوكلاء وموافقات العمليات الحساسة.
- اختبار استمرارية المهام بعد إغلاق التطبيق أو تعطل الاتصال.
- مراجعة صحة تقدير تكاليف نماذج AI وحدود الإنفاق.
- مراجعة مزامنة الملفات والتخزين والنسخ الاحتياطية والاستعادة الفعلية.
- التحقق من أن الاختبارات الحالية تغطي السلوك الفعلي لا النماذج فقط.
