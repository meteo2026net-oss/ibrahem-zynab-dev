# 19 — كتالوج تشغيلي أولي للمراكز C01–C04 وC08–C11

**الحالة:** DRAFT / DERIVED FROM RECOVERED SCREEN MAPS / PENDING OWNER REVIEW  
**الغرض:** تحويل أسماء الشاشات المعروفة في الملف 02 إلى مواصفات تشغيلية قابلة للمراجعة.  
**تنبيه:** أسماء الشاشات والأهداف أدناه مأخوذة من خريطة المراكز. أما تفاصيل المدخلات والمخرجات والصلاحيات والاختبارات فهي تفصيل هندسي أولي مستنتج، وليست قرارات اعتمدها المستخدم أو إثباتاً بأن الوظائف نُفذت.

## 1. قواعد القراءة والإغلاق

- معرف الشاشة بصيغة `Cxx-SCR-yy` معرف توثيقي مقترح لهذا الكتالوج، ويجب مطابقته مع أي معرف أصلي يعثر عليه لاحقاً.
- الأدوار المذكورة هي أدوار وظيفية عامة: مالك المشروع، محرر، مراجع، قارئ، مسؤول مؤسسة، مسؤول منصة، خدمة آلية. يجب ربطها بمصفوفة التفويض المركزية قبل التنفيذ.
- كل عملية كتابة يجب أن تتحقق خادمياً من العضوية والنطاق والصلاحية وحالة المورد، وأن تسجل التغيير.
- الاختبارات أدناه معرّفات مقترحة `DRAFT-AT` وليست حالات اختبار أصلية أو نتائج اجتياز.
- لا يغلق أي بند حتى تكتمل قواعد التحقق، حالات الخطأ، عقد API/event، ملكية البيانات، متطلبات الخصوصية، وسيناريوهات الاختبار وأدلة التنفيذ.

## 10. متطلبات عابرة يجب تطبيقها على كل وظيفة

يجب إضافة الحقول التالية إلى بطاقة كل وظيفة قبل تحويلها إلى مواصفة تنفيذية:
1. معرف الوظيفة ومصدرها وإصدارها وحالتها.
2. المالك الوظيفي والمركز المسؤول والخدمات التابعة.
3. الممثلون والأدوار ونطاق المؤسسة/المشروع/البيئة.
4. الشروط السابقة واللاحقة.
5. المدخلات: schema، required/optional، validation، limits.
6. المخرجات: schema، side effects، events، sensitivity.
7. حالات الخطأ: code، retryability، user message، recovery.
8. قواعد العمل والقيود والثوابت.
9. API/command/event contracts وإصداراتها.
10. ملكية البيانات ومصدر الحقيقة والاحتفاظ والحذف.
11. سجل التدقيق والموافقة المطلوبة.
12. التهديدات وضوابط الخصوصية والأمن.
13. اختبارات Unit/Integration/Contract/E2E/Negative.
14. معايير الأداء والإتاحة وإمكانية الوصول.
15. الاعتماديات ومخاطر الفشل وخطة التراجع.

## 11. ما يحتاج قراراً أو مصدراً ولا يجوز افتراضه

- الأسماء النهائية لمعرفات الشاشات إن كان المصدر الأصلي يستخدم ترميزاً آخر.
- الأدوار النهائية ومصفوفة الصلاحيات.
- أسماء كيانات قاعدة البيانات وحقولها وعلاقاتها النهائية.
- أسماء API والأحداث ومخططاتها.
- RTO/RPO والأرقام المالية وحدود الإنفاق.
- قائمة المنصات/الموصلات المعتمدة في الإصدار الأول.
- مستويات تصنيف البيانات والاحتفاظ القانونية.
- SH-17..SH-20.
- حالة Zero Trust وأي معيار امتثال.
- أي قبول أو نجاح اختبار لم ينفذ فعلياً.

## 12. بوابة المراجعة

يعد هذا الكتالوج تقدماً في تحويل خريطة الشاشات إلى مواصفات تشغيلية أولية، لكنه لا يغلق GAP-002..GAP-011 تلقائياً. يجب على مالك كل مركز مراجعة المحتوى، ومطابقة معرفاته مع المصدر، ثم استكمال عقود البيانات وواجهات API والصلاحيات والاختبارات. تظل الحالة العامة للحزمة DRAFT / RECOVERED PARTIALLY حتى إغلاق الفجوات واعتماد الوثيقة.
