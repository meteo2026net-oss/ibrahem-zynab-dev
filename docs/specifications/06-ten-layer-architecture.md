# 06 — المعمارية الرسمية ذات الطبقات العشر

**الحالة:** خط أساس معماري معتمد من حيث التقسيم والمسؤوليات؛ تفاصيل بعض التقنيات التنفيذية ما زالت قيد المراجعة.

## المبدأ الحاكم

اعتمد المستخدم معمارية معيارية متعددة الطبقات، مع استقلال الوحدات وواجهات موحدة وطبقة مركزية للصلاحيات والموافقات وسجل تدقيق مركزي وعزل للأعطال وتوافق للإصدارات. ويحكم جميع الطبقات مبدأ سلامة المشروع واستمرارية العمل: حماية البيانات، احترام حدود الصلاحيات، طلب الموافقات المطلوبة، توثيق التغييرات المهمة وقابليتها للمراجعة والتراجع، وعدم إعلان نجاح دون دليل واختبار.

## الطبقات العشر

| الرمز | الطبقة | المسؤولية الأساسية | أمثلة للمخرجات |
|---|---|---|---|
| L1 | واجهة المستخدم UI | التنقل العام، شاشات المراكز، RTL، التفضيلات، الوصول | واجهة تشغيل متماسكة |
| L2 | تجربة التصميم | Canvas، المكونات، Design System، المعاينات، التفاعلات | مستندات تصميم قابلة للتحرير |
| L3 | إدارة المشاريع | المؤسسات، مساحات العمل، المشاريع، المتطلبات، الأدوار وسير الموافقات | مشروع موثق ومعتمد |
| L4 | محرك الذكاء الاصطناعي | الوكلاء، المهارات، التخطيط، الذاكرة، التنسيق، سياسات المزود والتكلفة | خطط ومقترحات ومخرجات AI قابلة للمراجعة |
| L5 | محرك التنفيذ | البرمجة، المحولات، Sandbox، المهام، البناء والتشغيل المنضبط | تغييرات كود ومخرجات تنفيذ واختبار |
| L6 | البيانات والتكاملات | ملكية البيانات، قواعد البيانات، التخزين، APIs، الموصلات والأحداث | بيانات وعقود تكامل |
| L7 | الجودة والتحقق | الاختبارات، تتبع المتطلبات، العيوب، الأدلة وبوابات الجودة | تقارير قبول وجودة |
| L8 | الأمن والحوكمة | الهوية، الصلاحيات، العزل، الأسرار، الخصوصية، الموافقات والتدقيق | قرارات وصول وأدلة امتثال تقني |
| L9 | التشغيل والاستمرارية | المراقبة، الحوادث، التعافي، النسخ الاحتياطي، السعة والتكاليف التشغيلية | خدمة قابلة للمراقبة والاستعادة |
| L10 | البنية التحتية | بيئات الاستضافة، الحاويات، الشبكات، CI/CD، التخزين والموارد | بيئات تشغيل قابلة لإعادة الإنتاج |

## قواعد الحدود بين الطبقات

1. لا تتجاوز واجهة المستخدم سياسات الخادم أو صلاحياته.
2. محرك التصميم لا يعتمد على Angular داخلياً؛ Angular هو واجهة المصمم الأساسية وليس محرك التصميم.
3. محرك البرمجة مستقل عن إطار واجهة المصمم، ويعمل عبر واجهات ومحولات.
4. محرك الذكاء الاصطناعي يقترح وينسق، لكنه لا يمنح نفسه الصلاحيات ولا يتجاوز الموافقات.
5. كل تغيير تنفيذي يمر عبر صلاحيات وسياسات وفحوص واختبارات مناسبة.
6. لا يملك مركز لوحة التحكم البيانات الأصلية؛ يعرض ملخصات من المراكز المالكة.
7. الأمن والتدقيق والموافقات خدمات حاكمة مشتركة لا تُنسخ داخل كل مركز بصورة متعارضة.
8. التشغيل والاستمرارية مسؤولية مشتركة عبر الطبقة L9، وليست مركزاً مستقلاً إضافياً في القائمة النهائية للمراكز الأربعة عشر.
9. لكل نطاق مالك بيانات واحد وعقود واضحة للمستهلكين.
10. لا يُسمح بتجاوز بوابات الموافقة أو الاختبار عبر استدعاء داخلي أو وكيل بديل.

## أنماط التواصل

الاتجاه المعماري هو اختيار أسلوب التواصل وفق الحاجة:
- استدعاءات مباشرة للعمليات القصيرة ذات الاستجابة الفورية.
- أحداث للتغييرات التي تحتاج أكثر من مستهلك.
- طوابير ومهام خلفية للعمليات الطويلة.
- WebSocket أو SSE لتحديث الواجهة عند الحاجة.

هذه أنماط معمارية ينبغي تفصيل عقودها وسياساتها؛ لا يعني ذلك اعتماد وسيط رسائل أو منتج بعينه نهائياً.

## الاستقلالية والتعافي

- حدود واضحة بين الوحدات.
- مهلات وإعادة محاولة محدودة ومدروسة.
- idempotency للعمليات التي قد تتكرر.
- عزل الأعطال ومنع انتشارها.
- نقاط تحقق للمهام الطويلة.
- تتبع موحد للطلب والمهمة والمشروع.
- نسخ احتياطي واختبار استعادة فعلي.
- توافق وإصدارات للعقود والمحولات.

## متطلبات قبول معمارية

- ARCH-LAYER-01: لا تعتمد طبقة المحرك على مكونات واجهة Angular.
- ARCH-LAYER-02: لا تستطيع واجهة المستخدم تجاوز قرار صلاحية خادمي.
- ARCH-LAYER-03: كل خدمة تحدد مالك بياناتها وعقودها.
- ARCH-LAYER-04: يمكن تعطيل موصل معطل دون إسقاط بقية المنصة.
- ARCH-LAYER-05: تستأنف مهمة طويلة من نقطة تحقق بعد انقطاع مصرح به.
- ARCH-LAYER-06: لا تتكرر آثار عملية خارجية عند إعادة المحاولة.
- ARCH-LAYER-07: يسجل كل تغيير حساس الفاعل والسبب والموافقة والنتيجة.
- ARCH-LAYER-08: لا تعتبر لوحة التحكم مصدراً للحقيقة للبيانات المعروضة.
- ARCH-LAYER-09: تُختبر استعادة النسخ الاحتياطية عملياً.
- ARCH-LAYER-10: لكل عقد إصدار وسياسة توافق واختبارات.

## قرارات مفتوحة

- تفاصيل تقسيم الوحدات إلى عمليات نشر مستقلة مستقبلاً.
- منتج الطوابير/الأحداث النهائي.
- استراتيجية التخزين النهائي ومزود كل بيئة.
- مستويات الخدمة وأهداف RTO/RPO.
- الحدود الدقيقة بين محرك التنفيذ وخدمة البناء والنشر.
